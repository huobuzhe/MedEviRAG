## 1. 阶段目标与边界

### 1.1 阶段结束时"一定能做"的 6 件事

1. **一条命令重建环境**：在空目录里执行 `pip install -r requirements-dev.txt`，从阿里云 PyPI 镜像装齐全部依赖（含 torch 2.3.1+cu118），版本由 `requirements.txt` 锁定，Python 固定为 3.10.15；系统里的 Anaconda Python 3.6.5 一个字节都不被使用。
2. **四套配置的强类型分层**：`configs/app.yaml`、`models.yaml`、`retrieval.yaml`、`eval.yaml` 被 pydantic-settings 合并成一个强类型模型；环境变量用双下划线覆盖任意嵌套字段（`MEDEVIRAG__RETRIEVAL__TOPK=50` 立刻生效），且代理是**按 provider 分别配**的（`llm.providers.siliconflow.proxy: null` / `llm.providers.deepseek-official.proxy: http://127.0.0.1:7890`）。
3. **每个请求一行结构化日志**：JSON 单行输出，含 `trace_id`（contextvars 传播，跨线程/协程安全）与各节点 `latency_ms`；不 bind 时打印 `trace_id: "-"`，绝不抛异常。
4. **无 Key 可跑的全链路地基**：`LLMClient` 抽象 + `FakeLLM` 确定性桩（同 question 恒定输出、可注入"含非法引用 [C9]""该拒答""JSON 残缺"三个剧本），`uv run pytest -q` 在断网、无 API Key、无 Docker 的机器上全绿。
5. **环境自检可自助排障**：`uv run python -m medevirag.cli doctor` 打印自检表（python / uv / gpu / docker / llm:siliconflow / disk / config 共 7 行），只有 FAIL 才返回非 0 退出码——本机 docker daemon 未启动必须返回 0。
6. **容器与降级双轨**：`docker compose config` 校验通过的 5 服务 Compose（etcd + minio + milvus standalone + postgres:16 + redis:7，**不启用 pgvector**，全部带 healthcheck 与 `depends_on.condition`）；docker daemon 起不来时 `scripts/start_stack.ps1` 打印"降级到 Milvus Lite"并以退出码 0 收工。

### 1.2 阶段结束时"一定还不做"的 4 件事

1. **不解析任何 PDF、不切任何 chunk**：`ingest/` 下只建 `__init__.py` 空包，`chunks.jsonl` 不存在。Chunk 类型（00 §6.1）在 S0 只定义与校验，不产出实例。
2. **不建任何索引、不 embed、不做检索**：`index/` 全空；`data/indexes/milvus_lite.db` 与 `data/indexes/bm25/` 不存在；Milvus 只在 doctor 里做端点探测，不建 collection。
3. **不写生成与拒答逻辑**：`rag/` 全空。`FakeLLM` 只是桩，它不发起任何真实 HTTP（真调用属 S3）；`RefusalReason` 只定义 15 个枚举值，规则判定属 S4。
4. **不做评测集、不算任何 RAG 指标**：`eval/` 全空；00 §9 的 Recall@10 / MRR / P95 等指标在 S0 **一条都不测**（无索引无答案，测出来的数字都是假的），S0 只保证"将来测它们的脚手架在"。

## 4. 详细实施步骤

### T1 · 解释器与依赖锁定（1.0h）

**要解决的问题**：系统默认 `python` 是 Anaconda 3.6.5，任何 `from __future__ import annotations` 都会 `SyntaxError`；更隐蔽的是"本地能跑、CI 跑出另一个版本"——S0 若不做锁，后面 6 个阶段每次复现实验都要靠运气。

**关键思路**：用 `D:/Anaconda/envs/pytorch/python.exe -m venv --system-site-packages .venv` 得到 Python 3.10.15 并继承 conda pytorch 环境里的 torch cu118（不污染 Anaconda、不重下 2.67GB wheel），用 `requirements.txt` 锁定版本，用 pip 的 `-i` 镜像参数 把"阿里云 PyPI"设成默认源、把"pytorch cu118"设成**显式源**（只有 手动点名安装 点名要它的包才走它，避免整个依赖树被 pytorch 索引劫持）。

**容易踩的坑**：

- `pip install -r requirements-dev.txt` 在 `requirements.txt` 不存在时直接报 `error: Unable to find lockfile at requirements.txt, but --frozen was provided`。**顺序必须是 `pip freeze > requirements.txt` → `pip install -r requirements-dev.txt`"**，CI 里则只跑 `pip install -r requirements-dev.txt`（lock 已入库）。
- 只写 `[[tool.uv.index]]` 而不加 `explicit = true` 时，uv 会把 pytorch 索引当成额外候选源，可能装到版本对不上的 torch；手动点名安装 才是"点名"。
- 安装时打印 `warning: Failed to hardlink files; falling back to full copy`——F: 盘与 uv 缓存不同文件系统导致，**不是错误**；设 `UV_LINK_MODE=copy` 只是消掉日志。
- `requires-python` 的**上限**必须写 `<3.12`，否则 CI（可能默认 3.13）与本地（3.11）各解一遍依赖，lock 就白锁了。

### T2 · 强类型分层配置（1.0h）

**要解决的问题**：配置散落在 `os.getenv` 里会出三类事故——① 拼错 key 静默取默认值（`topk` 写成 `topK` 就永远 10）；② 全局 `HTTPS_PROXY` 把所有 HTTPS 都送进 Clash，而 SiliconFlow 走代理实测返回 **HTTP 000**；③ 实验跑出来的指标无法回答"当时是什么配置"。

**关键思路**：一个 `BaseSettings` 吃掉 4 个 YAML（`yaml_file` 传 tuple，后者覆盖前者），env 优先级高于 YAML，嵌套用 `env_nested_delimiter="__"`，最后把整个模型序列化取 sha256 得到 `config_hash()`——以后评测报告里的 `config_hash` 就是"当时配置"的指纹。

```python
# src/medevirag/common/config.py（核心片段）
from __future__ import annotations

import hashlib
import json
from functools import lru_cache
from pathlib import Path

from pydantic import BaseModel, Field
from pydantic_settings import (
    BaseSettings, PydanticBaseSettingsSource, SettingsConfigDict, YamlConfigSettingsSource,
)

CFG_DIR = Path(__file__).resolve().parents[3] / "configs"   # common/config.py -> F:\MedEviRAG\configs


class ProviderCfg(BaseModel):
    base_url: str
    model: str
    temperature: float = 0.0
    proxy: str | None = None          # ★ 按 provider 独立：siliconflow 必须 None
    api_key_env: str                  # 只存"环境变量名"，不存明文 Key
    timeout_s: float = 60.0


class LLMSection(BaseModel):
    default: str = "siliconflow"
    providers: dict[str, ProviderCfg] = Field(default_factory=dict)


class RetrievalSection(BaseModel):
    topk: int = 10
    dense_topk: int = 50
    sparse_topk: int = 50
    rrf_k: int = 60


class Settings(BaseSettings):
    model_config = SettingsConfigDict(
        env_prefix="MEDEVIRAG__",             # 外部变量必须以 MEDEVIRAG__ 开头
        env_nested_delimiter="__",            # MEDEVIRAG__RETRIEVAL__TOPK -> retrieval.topk
        env_file=(".env",),
        env_file_encoding="utf-8",
        extra="ignore",                       # 未知 env 不炸（宿主机常有一堆无关变量）
        yaml_file=tuple(str(CFG_DIR / f) for f in (
            "app.yaml", "models.yaml", "retrieval.yaml", "eval.yaml",
        )),
        yaml_file_encoding="utf-8",
    )

    app: AppSection = Field(default_factory=AppSection)
    llm: LLMSection = Field(default_factory=LLMSection)
    embedding: EmbeddingSection = Field(default_factory=EmbeddingSection)
    reranker: RerankerSection = Field(default_factory=RerankerSection)
    retrieval: RetrievalSection = Field(default_factory=RetrievalSection)
    budget: BudgetSection = Field(default_factory=BudgetSection)

    @classmethod
    def settings_customise_sources(
        cls,
        settings_cls: type[BaseSettings],
        init_settings: PydanticBaseSettingsSource,
        env_settings: PydanticBaseSettingsSource,
        dotenv_settings: PydanticBaseSettingsSource,
        file_secret_settings: PydanticBaseSettingsSource,
    ) -> tuple[PydanticBaseSettingsSource, ...]:
        # 优先级从高到低：显式入参 > 环境变量 > .env > YAML
        return (init_settings, env_settings, dotenv_settings,
                YamlConfigSettingsSource(settings_cls))

    def config_hash(self) -> str:
        payload = self.model_dump(mode="json", exclude={"app": {"log_level"}})
        blob = json.dumps(payload, ensure_ascii=False, sort_keys=True).encode("utf-8")
        return "sha256:" + hashlib.sha256(blob).hexdigest()[:12]


@lru_cache(maxsize=1)
def get_settings() -> Settings:
    return Settings()
```

### T3 · 结构化日志与 trace_id（0.5h）

**要解决的问题**：RAG 一次问答要经过 8 个节点，出错时"哪一步慢、哪一步空"必须靠一行日志回答；而 `structlog.threadlocal` 在 asyncio 与线程池之间会丢绑定，必须用 `contextvars`。

```python
# src/medevirag/common/logging.py（核心片段）
from __future__ import annotations

import contextvars
import logging
import sys
import uuid
from typing import Any

import structlog

_trace_id: contextvars.ContextVar[str] = contextvars.ContextVar("trace_id", default="-")


def new_trace_id() -> str:
    return uuid.uuid4().hex[:8]          # 8 位足够单机排查，日志更短


def bind_trace(trace_id: str | None = None) -> contextvars.Token[str]:
    return _trace_id.set(trace_id or new_trace_id())


def reset_trace(token: contextvars.Token[str]) -> None:
    _trace_id.reset(token)               # 必须 reset，否则线程池复用会串 trace


def current_trace_id() -> str:
    return _trace_id.get()


def _add_trace(_logger: Any, _name: str, event_dict: dict[str, Any]) -> dict[str, Any]:
    event_dict["trace_id"] = _trace_id.get()
    return event_dict


def configure(level: str = "INFO", json_output: bool = True) -> None:
    logging.basicConfig(format="%(message)s", stream=sys.stdout, level=level)
    processors: list[Any] = [
        _add_trace,
        structlog.contextvars.merge_contextvars,
        structlog.processors.TimeStamper(fmt="iso", key="ts"),
        structlog.processors.add_log_level,
    ]
    processors.append(
        structlog.processors.JSONRenderer(ensure_ascii=False)   # 中文不转 \uXXXX
        if json_output else structlog.dev.ConsoleRenderer()
    )
    structlog.configure(
        processors=processors,
        wrapper_class=structlog.make_filtering_bound_logger(
            getattr(logging, level.upper(), logging.INFO)
        ),
        logger_factory=structlog.PrintLoggerFactory(sys.stdout),
        cache_logger_on_first_use=True,
    )


def get_logger(name: str) -> Any:
    return structlog.get_logger(name)
```

```python
# src/medevirag/common/timing.py —— "每请求一行日志含各节点耗时"的实现
from __future__ import annotations

import time
from collections.abc import Iterator
from contextlib import contextmanager
from typing import Any

from medevirag.common.logging import get_logger

log = get_logger("medevirag.node")


@contextmanager
def node_timer(node: str, trace_id: str, **extra: Any) -> Iterator[dict[str, Any]]:
    started = time.perf_counter()        # 单调时钟，不受系统时间调整影响
    box: dict[str, Any] = {}
    try:
        yield box                        # 节点内部可往 box 里塞 hits/candidates 等指标
    finally:
        latency_ms = round((time.perf_counter() - started) * 1000, 1)
        log.info(
            "node_done", node=node, latency_ms=latency_ms, trace_id=trace_id,
            **{k: v for k, v in extra.items() if isinstance(v, (int, float, str, bool))},
            **box,
        )
```

实测输出（本机原样，注意 `ensure_ascii=False` 让中文不被转义）：

```
{"node": "retrieve", "latency_ms": 128.4, "hits": 50, "event": "node_done", "trace_id": "7f3a9c1e", "ts": "2026-10-23T16:20:39.890721Z", "level": "info"}
{"node": "rerank", "latency_ms": 41.2, "event": "node_done", "trace_id": "-", "ts": "2026-10-23T16:20:39.891013Z", "level": "info"}
```

**容易踩的坑**：

- `structlog.configure` 默认带 `ConsoleRenderer` 且**没有** `TimeStamper`，直接 `log.info("x", latency_ms=1)` 输出形态完全不是 JSON——先 `configure()` 再取 logger。
- `JSONRenderer` 不传 `ensure_ascii=False` 时中文变成 `\u8bca\u5ba4`，日志里 grep 中文关键词全部失效。
- `contextvars.Token` 只能在其被 `set` 的同一上下文里 `reset`；在线程池 `run_in_executor` 里 set 的 trace 不会自动回到主线程——跨线程要在提交任务时显式 `bind_trace(tid)`。
- 用 `os.getenv("trace_id")` 当备用通道是反模式：多进程/多请求下会互相覆盖。

### T4 · 共享类型：Chunk 与答案契约（0.75h）

**要解决的问题**：00 §6.1 的 Chunk 有 22 个字段和 3 条硬约束。若 S1 的 chunker 与 S2 的 store 各写一份 dict，字段名漂移（`pageStart` / `page_start`）会在 S3 才暴露，届时 10 个文件都要改。

**关键思路**：用 `@dataclass(frozen=True, slots=True)` 定义，**把 00 §6.1 的三条硬约束写成 `__post_init__` 校验**——约束住在类型里，S1 每产一个 chunk 都在自查。

```python
# src/medevirag/common/types.py（Chunk 片段，字段与 00 §6.1 逐字段同名）
from __future__ import annotations

import hashlib
from dataclasses import dataclass, field
from enum import Enum
from typing import Literal

DocType = Literal["guideline", "consensus", "paper", "manual"]
ChunkType = Literal["paragraph", "recommendation", "table", "figure_caption", "list"]
EvidenceLevel = Literal["A", "B", "C", "D", "unknown"]
RecStrength = Literal["I", "IIa", "IIb", "III", "unknown"]
GradeSystem = Literal["GRADE", "牛津", "指南自定", "unknown"]
Status = Literal["answered", "partial", "refused"]


@dataclass(frozen=True, slots=True)
class Locator:
    page: int
    block_index: int
    bbox: tuple[float, float, float, float] | None = None


@dataclass(frozen=True, slots=True)
class Chunk:
    chunk_id: str            # "CN-HTN-2024#3.2.1#c02"
    parent_id: str           # "CN-HTN-2024#3.2.1"（small-to-big 回填用）
    doc_id: str
    doc_title: str
    doc_type: DocType
    publisher: str
    publish_year: int
    lang: Literal["zh", "en"]
    section_path: list[str]
    section_level: int
    page_start: int
    page_end: int
    chunk_type: ChunkType
    text: str
    context_header: str
    evidence_level: EvidenceLevel
    rec_strength: RecStrength
    grade_system: GradeSystem
    token_len: int
    content_hash: str        # "sha256:..."
    locator: Locator

    def __post_init__(self) -> None:
        if not self.content_hash.startswith("sha256:"):
            raise ValueError("content_hash 必须带 sha256: 前缀")
        if self.page_start > self.page_end:
            raise ValueError("page_start 不能大于 page_end")
        if self.page_start == self.page_end and self.locator.bbox is None:
            raise ValueError("page_start==page_end 时 bbox 不得为空，否则无法回链")
        if self.chunk_type in ("table", "recommendation") and self.page_start != self.page_end:
            raise ValueError("table/recommendation 禁止跨页合并")   # 00 §6.1 硬约束

    @staticmethod
    def compute_hash(text: str) -> str:
        return "sha256:" + hashlib.sha256(text.encode("utf-8")).hexdigest()
```

**容易踩的坑**：

- `str, Enum` 混用后 `RefusalReason.OFF_DOMAIN == "off_domain"` 为 True，但 `json.dumps` 需要 `.value`；写日志时用 `reason.value`，不要直接 `f"{reason}"`（会打印 `RefusalReason.OFF_DOMAIN`）。
- `frozen=True` 与 `list` 字段共存时对象不可哈希，别拿 Chunk 当 dict key；需要去重就用 `chunk_id`。
- 缺字段必须用 `unknown` 而不是 `None`（00 §6.1 明文要求）：`Literal` 里没有 `None`，写 `None` 直接被类型检查拒绝——这正是我们要的强约束。

### T5 · 错误体系（0.25h）

**要解决的问题**：上层要能区分"该重试"（LLM 429、Milvus 未就绪）与"重试也没用"（配置错、预算超额）。用裸 `Exception` 的后果是到处 `except Exception: time.sleep(1)`，把不可恢复错误也重试三遍。

```python
# src/medevirag/common/errors.py（全量，短小）
from __future__ import annotations

from typing import Any


class MedEviRAGError(Exception):
    code: str = "medevirag_error"
    retryable: bool = False

    def __init__(self, message: str, *, detail: dict[str, Any] | None = None) -> None:
        super().__init__(message)
        self.message = message
        self.detail = detail or {}

    def to_dict(self) -> dict[str, Any]:
        return {"code": self.code, "message": self.message,
                "retryable": self.retryable, "detail": self.detail}


class ConfigError(MedEviRAGError):
    code = "config_error"                      # retryable=False（继承默认）


class MissingEnvError(ConfigError):
    code = "missing_env"


class ExternalServiceError(MedEviRAGError):
    code = "external_service_error"
    retryable = True                           # 网络/服务端问题，可退避重试


class LLMCallError(ExternalServiceError):
    code = "llm_call_error"


class VectorStoreError(ExternalServiceError):
    code = "vector_store_error"


class HealthCheckError(MedEviRAGError):
    code = "health_check_error"
    retryable = True                           # doctor 失败后允许重试


class BudgetExceeded(MedEviRAGError):
    code = "budget_exceeded"                   # retryable=False：预算烧完重试没用
```

实测：`LLMCallError("429 rate limited", detail={"provider":"siliconflow"}).to_dict()` → `{'code': 'llm_call_error', 'message': '429 rate limited', 'retryable': True, 'detail': {'provider': 'siliconflow'}}`。

**容易踩的坑**：`retryable` 必须是**类属性**而不是构造参数——否则重试装饰器要在实例化后才能判断，而异常在到达装饰器前就已抛出；子类改 `code` 时不会自动拼接父类前缀（有意如此，便于日志按 code 聚类）。

### T6 · LLMClient 抽象 + FakeLLM 确定性桩（1.0h）

**要解决的问题**：ADR-06 与 00 §13.1 都要求"开发期与 CI 一律用桩、真实 API 只在阶段末评测时用"。桩必须是**确定性**的：同一 question 永远同一输出，否则单测断言写不出来，CI 会变成噪声源。

**关键思路**：用 `typing.Protocol` 定义端口（零依赖），`FakeLLM` 用 `sha256(system + "\x00" + user)[:12]` 当"问题指纹"塞进答案——既能断言"同问同答"，又能断言"不同问题产生不同输出"（防止桩退化成常量字符串）。

```python
# src/medevirag/common/llm.py（核心片段）
from __future__ import annotations

import hashlib
import json
from dataclasses import dataclass, field
from typing import Literal, Protocol

ScriptMode = Literal["normal", "bad_citation", "refuse", "malformed_json"]


@dataclass(frozen=True)
class LLMRequest:
    system: str
    user: str
    temperature: float = 0.0
    max_tokens: int = 1024


@dataclass(frozen=True)
class LLMResponse:
    text: str
    prompt_tokens: int = 0
    completion_tokens: int = 0
    model: str = "fake"
    cached: bool = False

    @property
    def total_tokens(self) -> int:
        return self.prompt_tokens + self.completion_tokens


class LLMClient(Protocol):
    def complete(self, req: LLMRequest) -> LLMResponse: ...     # 端口：S3 的 HTTP 客户端也满足它


@dataclass
class FakeLLM:
    mode: ScriptMode = "normal"
    model: str = "fake-deterministic"
    calls: list[LLMRequest] = field(default_factory=list)      # CI 断言 len(calls) == 0 用

    def _key(self, req: LLMRequest) -> str:
        h = hashlib.sha256((req.system + "\x00" + req.user).encode("utf-8"))
        return h.hexdigest()[:12]

    def complete(self, req: LLMRequest) -> LLMResponse:
        self.calls.append(req)
        key = self._key(req)
        if self.mode == "refuse":
            payload = {"answer": "", "status": "refused", "refusal_reason": "off_domain"}
        elif self.mode == "bad_citation":
            payload = {"answer": f"推荐使用氨氯地平 5mg qd [C9]。key={key}", "status": "answered"}
        elif self.mode == "malformed_json":
            text = f'{{"answer": "缺少右括号 key={key}"'          # 故意不闭合，测解析兜底
            return LLMResponse(text=text, prompt_tokens=len(req.user) // 4,
                               completion_tokens=8, model=self.model)
        else:
            payload = {"answer": f"固定答案 key={key} [C1]", "status": "answered"}
        text = json.dumps(payload, ensure_ascii=False, sort_keys=True)
        return LLMResponse(
            text=text,
            prompt_tokens=max(1, len(req.user) // 4),          # 粗估 4 字符 ≈ 1 token
            completion_tokens=max(1, len(text) // 4),
            model=self.model,
        )
```

from __future__ import annotations

from medevirag.common.errors import BudgetExceeded
from medevirag.common.logging import get_logger

log = get_logger("medevirag.budget")


class TokenLedger:
    def __init__(self) -> None:
        self.total = 0
        self.calls = 0

    def add(self, usage: dict[str, int], *, node: str, warn_at: int, hard_at: int) -> None:
        self.total += int(usage.get("total_tokens", 0))
        self.calls += 1
        if self.total > hard_at:
            raise BudgetExceeded(f"{node}: 累计 {self.total} > 硬上限 {hard_at}")
        if self.total > warn_at:
            log.warning("token 预算告警", node=node, total=self.total, calls=self.calls)


LEDGER = TokenLedger()      # 进程级单例；CI 断言 LEDGER.calls == 0

### T9 · doctor 自检 + pytest 骨架 + CI（0.5h）

**要解决的问题**：00 §8 要求 `uv run python -m medevirag.cli doctor` 输出环境自检表；CI 必须"不依赖 docker、不依赖 API Key"，否则门禁会因网络随机红灯。

**关键思路**：每项检查返回 `CheckRow(name, status, detail)`，三态 OK/WARN/FAIL；**只有 FAIL 才非 0 退出**（docker daemon 未启动、盘不是 200GB 空闲，这些都是 WARN）。

```python
# src/medevirag/cli.py（核心片段）
from __future__ import annotations

import argparse
import json
import shutil
import subprocess
import sys
from dataclasses import dataclass
from pathlib import Path

from medevirag.common.config import get_settings

STATUS_OK, STATUS_WARN, STATUS_FAIL = "OK", "WARN", "FAIL"


@dataclass
class CheckRow:
    name: str
    status: str
    detail: str


def _run(cmd: list[str], timeout: int = 20) -> tuple[int, str]:
    try:
        p = subprocess.run(cmd, capture_output=True, text=True, timeout=timeout, check=False)
        return p.returncode, (p.stdout or p.stderr or "").strip()
    except (OSError, subprocess.TimeoutExpired) as exc:
        return 1, type(exc).__name__


def check_docker() -> CheckRow:
    if shutil.which("docker") is None:
        return CheckRow("docker", STATUS_WARN, "未安装 -> 降级 Milvus Lite")
    rc, _ = _run(["docker", "info", "--format", "{{.ServerVersion}}"])
    if rc != 0:
        return CheckRow("docker", STATUS_WARN, "daemon 未启动 -> 降级 Milvus Lite")
    return CheckRow("docker", STATUS_OK, "daemon ok")


def check_proxy() -> CheckRow:
    from medevirag.common.llm_client import probe_endpoint

    cfg = get_settings()
    target = cfg.llm.providers[cfg.llm.default]
    ok, detail = probe_endpoint(target.base_url, proxy=target.proxy, timeout=5.0)
    return CheckRow(f"llm:{cfg.llm.default}", STATUS_OK if ok else STATUS_WARN, detail)


CHECKS = (check_python, check_uv, check_gpu, check_docker, check_proxy, check_disk, check_config)


def doctor(as_json: bool = False) -> int:
    rows = [fn() for fn in CHECKS]
    if as_json:
        print(json.dumps([r.__dict__ for r in rows], ensure_ascii=False, indent=2))
    else:
        w = max(len(r.name) for r in rows)
        print(f"{'检查项'.ljust(w)}  结果  详情")
        print("-" * (w + 60))
        for r in rows:
            print(f"{r.name.ljust(w)}  {r.status:<4}  {r.detail}")
    return 0 if all(r.status != STATUS_FAIL for r in rows) else 1
```

## 5. 知识点讲解

### 5.1 依赖锁定与可复现构建

**是什么**：`requirements.txt` 是 universal 依赖快照，记录**每个包的确切版本 + 下载源 + 平台标记**；与 `pip freeze` 不同，它按平台拆 marker，所以 Windows 的 torch 与 Linux 的 torch 能锁进同一个 lock。

**为什么需要**：S2 的 Recall@10 若不能复现，就只是"某天某台机器的传说"。依赖漂移 1 个 minor，BM25 分词或 numpy 的 `float32` 累加顺序都可能让指标动 1–2 个点。

**在本项目怎么用**：`pip freeze > requirements.txt` 生成并入库；`pip install -r requirements-dev.txt` 是唯一合法安装命令；CI 与 Dockerfile 全部 `--frozen`。lock 里 torch 那行本机实测为：

```
{ name = "torch", specifier = "==2.3.1", index = "https://download.pytorch.org/whl/cu118" }
```

**常见误解**："锁了 lock 就万事可复现"——不，CUDA 驱动与 GPU 型号没锁（本机驱动 596.36）；跨机器复现要求报告里同时记 `config_hash` 与 `nvidia-smi` 输出。

### 5.2 配置分层的优先级模型

**是什么**：有序广播：**显式入参 > 环境变量 > .env > YAML > 代码默认值**。pydantic-settings 用 `settings_customise_sources` 返回元组的**顺序**表达优先级，靠前者赢。

**为什么需要**：同一次评测要跑 topk=10 / 50 / 100 三组。若靠改 YAML，三次跑完无法确定哪份 YAML 对应哪组数字；若靠 env，命令行前缀就把实验条件写进 shell 历史，也不污染仓库文件。

**在本项目怎么用**：日常开发 YAML 定默认（`retrieval.topk: 10`），扫参用 `MEDEVIRAG__RETRIEVAL__TOPK=50` 覆盖；`config_hash()` 取生效配置 sha256 前 12 位，写进 `eval_runs.config_hash`（00 §6.2）。

**常见误解**："env 覆盖要写一整套解析逻辑"。嵌套映射规则是 `env_prefix + 每层用 __ 连接`：`MEDEVIRAG__LLM__PROVIDERS__SILICONFLOW__PROXY` ↔ `llm.providers.siliconflow.proxy`，写对分隔符就零代码。

### 5.3 contextvars 与结构化日志的传播

**是什么**：`contextvars.ContextVar` 是**每协程/每线程独立**的隐式上下文，asyncio 创建任务时复制一份，天然适合放 `trace_id`。

**为什么需要**：一次问答跨 8 个节点。若 `trace_id` 靠函数参数逐层传，每个签名都要多一个参数且中间漏传就断链；用全局变量在 100 并发下会串号（日志里出现别人的 trace_id）。

**在本项目怎么用**：请求入口 `bind_trace()`，每节点用 `node_timer(node, current_trace_id())` 输出 `latency_ms`；finally 里 `reset_trace(token)`。实测未 bind 时输出 `trace_id: "-"`，不会抛错。

**常见误解**：以为 `structlog.threadlocal.bind_threadlocal` 等价——在线程池 `run_in_executor` 里绑定的值不会回到事件循环线程，取到的是 `trace_id="-"`。

### 5.4 确定性桩与测试金字塔

**是什么**：桩（stub）是返回固定结果的假实现；确定性指**同一输入永得同一输出**，靠输入哈希而非随机源实现。

**为什么需要**：真实 LLM 每次输出不同，`assert answer == "..."` 必然失败；更致命的是单次调用 3–8s 且偶发 429，门禁会变成噪声源。00 §13.1 的口径是：**CI 中真实 API 调用数必须为 0**。

**在本项目怎么用**：4 个剧本覆盖后续阶段的关键失败路径——`normal`（带 [C1]）、`bad_citation`（带不存在的 [C9]，验 ADR-04 后校验能否拦下）、`refuse`（应拒答）、`malformed_json`（验解析兜底）。测试金字塔建议 **单测:集成:端到端 = 70:25:5**，S0 只交 5 个单测占位。

**常见误解**："桩测过等于真模型没问题"。桩只验证**管线正确性**（字段流转、异常分支），模型质量靠 S5 离线评测报告（忠实度 ≥0.80），两者不可互替。

### 5.5 端口—适配器与按 provider 的依赖注入

**是什么**：领域代码只依赖**协议**（`typing.Protocol`），具体实现（FakeLLM / OpenAI 兼容 / 本地 vLLM）在边界注入。

**为什么需要**：00 §3 把"Key 缺失或额度耗尽"列为黄灯风险。若 `rag/generator.py` 直接写死 `base_url` 与 `proxies=`，换提供方要改业务代码，也无法在单测里替换。

**在本项目怎么用**：`LLMClient` 只声明 `complete(LLMRequest) -> LLMResponse`；S3 的真实实现从 `configs/models.yaml` 的 `providers` 取 `base_url/model/proxy/api_key_env`——**siliconflow 直连、deepseek-official 走 7890**，切换不改业务代码。

**常见误解**：以为 Protocol 必须 `@runtime_checkable` 才能当类型用。静态检查（mypy strict）在编译期就校验结构；`isinstance` 只在需要运行时分派时才要 descriptor。

### 5.6 错误分类与指数退避

**是什么**：把异常分为 retryable（429/503/连接重置）与 non-retryable（配置错、参数非法、预算超限），重试只对前者生效。

**为什么需要**：无差别重试会把"401 Key 无效"重试 3 次白等；更糟的是把"预算已超"当临时故障，越重试越烧钱。

**在本项目怎么用**：`ExternalServiceError.retryable = True`；`ConfigError/BudgetExceeded = False`。退避公式 **delay = min(0.5 × 2^n, 8s) + U(0, 0.1)，n = 0,1,2**，总等待约 0.5+1+2 = 3.5s，落在 P95 6s 预算内可接受。

**常见误解**："重试越多越稳"。在 P95 ≤ 6s 约束下一次重试就吃掉 0.5–1.5s；generation 段的 3.5s 预算里最多允许 1 次重试。

### 5.7 Milvus Lite 与 standalone 的差异边界

**是什么**：standalone 是 etcd+minio+milvus 三容器的分布式形态；Milvus Lite 是**纯 Python 进程内**实现（milvus-lite 3.2.2 的 wheel 是 `py3-none-any`、276845 字节，底层 `faiss-cpu` + `grpcio`），`MilvusClient("./data/indexes/milvus_lite.db")` 直接起本地 gRPC 服务。

**为什么需要**：本机 `com.docker.service` 为 STOPPED、`docker info` 报 `npipe:////./pipe/dockerDesktopLinuxEngine` 连不上。没有 Lite 路径，"无 Docker 全绿"的验收无法达成。

**在本项目怎么用**：一个 `MILVUS_URI` 切两轨——有 Docker 用 `http://127.0.0.1:19530`，没有就 `./data/indexes/milvus_lite.db`。本机实测：建 collection（`dimension=4, metric_type="COSINE"`）→ insert → search 全通，返回分数 0.9999 / 0.8387（import 14.8s，首次 client 3.2s）。

**常见误解**："`pymilvus[milvus_lite]` 在 Windows 上装得上"。**装不上**：pymilvus 3.0.2 的 `requires_dist` 里该 extra 的条件写死 `sys_platform != "win32"`，且 milvus-lite 2.4.x/2.5.x 只有 manylinux/macosx 轮。必须**显式**写 `milvus-lite>=3.1`。

### 5.8 容器就绪探针与启动顺序

**是什么**：`healthcheck` 定义"怎么判断容器内**服务**就绪"；`depends_on.condition: service_healthy` 让依赖方**等到**对方健康。

**为什么需要**：milvus 启动即连 etcd 2379 与 minio 9000。只写 `depends_on: [etcd]` 时顺序对了但服务未就绪，milvus 报 `context deadline exceeded` 退出重启，人看到的是"compose up 卡住"。

**在本项目怎么用**：etcd 用 `etcdctl endpoint health`；minio 用 `curl -f /minio/health/live`；milvus 用 `curl -f localhost:9091/healthz` 且 `start_period: 90s`；PG 用 `pg_isready`；redis 用 `redis-cli ping`。

**常见误解**：`start_period` 不是"等多久才第一次检查"，而是"这段时间内失败不计入 retries"的宽限期。

### 5.9 时延预算的分解

**是什么**：把 P95 ≤ 6s（00 §9）拆到链路每段并留余量。

**在本项目怎么用**：`retrieval ≤ 800ms`（dense 50 ∥ sparse 50）、`rerank ≤ 600ms`（20 候选交叉编码）、`generation ≤ 3.5s`（含 1 次重试余量）、`序列化与校验 ≤ 300ms`，合计 5.2s，余量 0.8s。S0 的 `node_timer` 就是这套预算的执行器：任何节点超预算都要能从一行日志里看出来。

**常见误解**："P95 约等于均值的 1.5 倍"。本机 bge-m3 首次 import 就要 14.8s，长尾由首次加载主导，所以 S6 必须预热——P95 只能实测，不能推算。

## 7. 常见问题与排查

### FAQ-1 · `SyntaxError: future feature annotations is not defined`

**现象**：刚写的 `from __future__ import annotations` 在第 1 行就报错。
**原因**：用的是系统 `python`（Anaconda 3.6.5），该特性 3.7 才有。
**解法**：所有命令前缀 `uv run`，确认 `uv run python -V` 输出 3.10.15。**不要** `conda activate`，也不要改系统 PATH。

### FAQ-2 · PowerShell 脚本报"字符串缺少终止符"，但文件看起来完全正常

**现象**：`字符串缺少终止符` / `缺少右"}"` / `缺少语句结束符`，指向一行没有语法错误的代码。
**原因**：PS 5.1 把**无 BOM 的 UTF-8** .ps1 当 ANSI 读，中文注释的字节被误读，引号配对被破坏。本机实测：同一份 `start_stack.ps1` 无 BOM → 三个解析错误；加 UTF-8 BOM → `PARSE OK`。
**解法**：脚本存 **UTF-8 with BOM**。Git Bash 里补 BOM：

```bash
python -c "p='scripts/start_stack.ps1';d=open(p,'rb').read();open(p,'wb').write(b'\xef\xbb\xbf'+d)"
```

PowerShell 里检查与补写：

```powershell
$p = "scripts\start_stack.ps1"
$bytes = [System.IO.File]::ReadAllBytes($p)
if (-not ($bytes[0] -eq 0xEF -and $bytes[1] -eq 0xBB -and $bytes[2] -eq 0xBF)) {
    $text = [System.IO.File]::ReadAllText($p, [System.Text.Encoding]::UTF8)
    [System.IO.File]::WriteAllText($p, $text, (New-Object System.Text.UTF8Encoding($true)))
}
```

### FAQ-3 · 全局代理把 SiliconFlow 打成 HTTP 000（"网络三件套"真正的坑）

**现象**：设了 `HTTPS_PROXY=http://127.0.0.1:7890` 后，doctor 的 `llm:siliconflow` 由 OK 变 WARN，curl 返回 `000`；清掉代理立刻恢复 401。
**原因**：Clash 规则对 `api.siliconflow.cn` 走了不通的出口（实测 `-x http://127.0.0.1:7890` → HTTP 000），而 `api.deepseek.com` **恰好相反**（直连 000、必须走代理）。**全局 `HTTPS_PROXY` 无法同时满足两者。**
**解法**：① 环境变量里**不设**全局代理（`env_setup.ps1` 默认清空）；② 需要代理的 provider 在 `configs/models.yaml` 里单点写 `proxy`；③ 发请求时 `urllib.request.ProxyHandler({})` 显式禁代理。**"网络三件套"的正确含义是：包源走阿里云镜像、权重走 ModelScope、LLM 按 provider 分代理**——不是"所有请求套同一个代理"。

### FAQ-4 · `hf-mirror.com` 下载 bge-m3 卡住或 5s 超时 000

**现象**：`AutoTokenizer.from_pretrained("BAAI/bge-m3")` 长时间无响应；curl 根域 0.72s 可达，但 `/BAAI/bge-m3/resolve/main/config.json` 返回 000。
**原因**：hf-mirror 只有根域可达，**模型文件路径实测不可用**（25s 超时，经代理同样 000）；huggingface.co 直连与经代理都是 000。
**解法**：改走 ModelScope——

```bash
uv pip install modelscope
uv run modelscope download --model BAAI/bge-m3 --local_dir models/bge-m3
uv run modelscope download --model BAAI/bge-reranker-v2-m3 --local_dir models/bge-reranker-v2-m3
```

配置里 `HF_ENDPOINT=https://www.modelscope.cn` 仅对 ModelScope 有镜像的模型有效；**最可靠是预下载到 `models/bge-m3` 并用本地路径加载**（`configs/models.yaml` 的 `embedding.model_path` 已是本地路径）。

### FAQ-5 · Windows 上 Milvus Lite "装了但起不来"

**现象**：`import milvus_lite` 失败，或装到 2.4.x/2.5.x 后 `MilvusClient("./x.db")` 直接抛错。
**原因**：pymilvus 3.0.2 的 `requires_dist` 里 milvus-lite 的 extra 条件写死 `sys_platform != "win32"`，实际**不会**在 Windows 装它；而 milvus-lite 2.4.x/2.5.x 的 win_amd64 轮子数为 **0**。
**解法**：显式依赖 `milvus-lite>=3.1`（3.2.2 是 `py3-none-any` 纯 Python 轮，276845 字节，依赖 faiss-cpu/grpcio/pyarrow）。验证：

```bash
uv run python -c "import importlib.metadata as m, milvus_lite; print(m.version('milvus-lite'))"
# 预期输出：3.2.2（≥3.1 即可）
```

### FAQ-6 · `failed to connect to the docker API at npipe:////./pipe/dockerDesktopLinuxEngine`

**现象**：`docker info` 失败；`sc query com.docker.service` 显示 `STATE:1 STOPPED`、`WIN32_EXIT_CODE: 1077`。
**原因**：Docker Desktop 未启动（本机基线如此，不是配置错误）。
**解法**：这不是 S0 的阻塞项。跑 `powershell -NoProfile -File scripts/start_stack.ps1`，它检测失败后打印"降级到 Milvus Lite"并 `exit 0`，同时设 `MILVUS_URI=./data/indexes/milvus_lite.db`。要用容器栈就手动启动 Docker Desktop 再重跑；只做语法校验用 `docker compose config`（不需要 daemon）。

### FAQ-7 · curl 发中文 JSON 给 LLM，返回乱码甚至阿拉伯语

**现象**：`curl -d '{"messages":[{"content":"高血压用药"}]}' ...` 返回内容不可读。
**原因**：Git Bash 下命令行参数经 Windows 代码页转换，UTF-8 中文被破坏，模型收到乱码后按乱码作答（本机实测出现过阿拉伯语回复）。
**解法**：body 先落文件再发——

```bash
printf '%s' '{"model":"deepseek-ai/DeepSeek-V4.1-Flash","messages":[{"role":"user","content":"高血压一线用药"}]}' > /tmp/body.json
curl -s --noproxy '*' -H "Content-Type: application/json; charset=utf-8" \
     -H "Authorization: Bearer $SILICONFLOW_API_KEY" \
     --data-binary @/tmp/body.json \
     https://api.siliconflow.cn/v1/chat/completions
```

Python 侧统一 `json.dumps(obj, ensure_ascii=False).encode("utf-8")`（`llm_client.post_json` 已如此实现）；PowerShell 侧用 `[Text.Encoding]::UTF8.GetBytes($json)` 作为 `-Body`，不要直接传字符串。

### FAQ-8 · 每次 `pip install -r requirements.txt` 都刷 `warning: Failed to hardlink files; falling back to full copy`

**现象**：安装变慢，日志反复出现该警告。
**原因**：uv 缓存目录与项目目录不在同一文件系统（缓存在 C:、项目在 F:），无法硬链接。
**解法**：设 `UV_LINK_MODE=copy`（`env_setup.ps1` 已设）消掉警告；或把 `UV_CACHE_DIR` 指到 F: 盘。**这不是错误**，只是失去硬链接的空间与速度优化。

### FAQ-9 · `MEDEVIRAG__RETRIEVAL__TOPK=50` 设了但打印还是 10

**现象**：环境变量明明设了，`get_settings().retrieval.topk` 恒为 10。
**原因**：三种可能——① 变量名写成单下划线（`MEDEVIRAG_RETRIEVAL_TOPK`），与 `env_prefix + __` 规则不匹配；② PowerShell 5.1 里用了 `VAR=val cmd` 前缀语法（5.1 不支持，变量根本没设）；③ 同进程内 `lru_cache` 已缓存旧值。
**解法**：PowerShell 用 `$env:MEDEVIRAG__RETRIEVAL__TOPK="50"` 后**重开进程**；先自检变量是否真进去了：

```bash
uv run python -c "import os;print(os.environ.get('MEDEVIRAG__RETRIEVAL__TOPK'))"
```

### FAQ-10 · 日志里中文变成 Unicode 转义序列，grep 中文零命中

**现象**：JSON 单行结构正确，但中文全部变成 6 字符的 `\uXXXX` 形式。
**原因**：`JSONRenderer()` 默认 `ensure_ascii=True`；另外 Windows 终端默认代码页 936 也会让输出看起来是乱码。
**解法**：`JSONRenderer(ensure_ascii=False)`（`logging.configure` 已如此）；终端设 UTF-8——Git Bash `chcp.com 65001`，PowerShell `[Console]::OutputEncoding=[System.Text.Encoding]::UTF8`，或给 Python 设 `PYTHONUTF8=1`。

### FAQ-11 · `pip install -r requirements-dev.txt` 报 `Unable to find lockfile`

**现象**：刚 clone 或删过 lock 的机器上第一条命令就红，报错含 `Unable to find lockfile at requirements.txt, but --frozen was provided`。
**原因**：`--frozen` 表示"只按现有 lock 装、不许改它"，lock 不存在时直接失败；而 `requirements.txt` 必须入库。
**解法**：本地首次 `pip freeze > requirements.txt` 再 `pip install -r requirements-dev.txt`；确认 `git ls-files requirements.txt` 有输出；检查 `.gitignore` 里没有 `*.lock` 这类通配。

### FAQ-12 · `docker compose up` 卡在 milvus，日志报 `context deadline exceeded`

**现象**：`milvus` 容器反复重启，`docker compose ps` 显示 `Restarting`。
**原因**：只写了 `depends_on: [etcd, minio]`（短语法），它只保证容器**启动顺序**，不保证服务**就绪**；milvus 启动即连 etcd 2379 与 minio 9000，连不上就退。
**解法**：改成 `condition: service_healthy` 并为 etcd/minio 补 `healthcheck`（§4 T7 已给完整写法）；等 etcd/minio 都显示 `(healthy)` 再让 milvus 起；冷启动慢，给 `start_period: 90s`。

## 8. 面试可讲点

1. **"我用 uv 建了跨平台可复现的 Python 环境，并把 CUDA 版 torch 隔离到显式索引里。"**
   —— 为什么这么做：宿主机默认 Python 是 Anaconda 3.6.5，直接跑会 `SyntaxError`。被否决的方案是 `conda create` + `requirements.txt`，理由是该方案无法表达平台 marker（Windows 锁出来的环境在 Linux CI 上装不上），且复现依赖机器状态而不是一份文件。

2. **"配置做成强类型分层 + 双下划线 env 覆盖 + 配置哈希，代理按 provider 单独配。"**
   —— 为什么：全局 `HTTPS_PROXY` 会把 SiliconFlow 打成 HTTP 000，而 DeepSeek 官方域名又必须走代理，二者不可共存。被否决的方案是"读 YAML 用 dict 手动 `get()`"，理由是拼错 key 会静默取默认值，且无法回答"这个指标是哪套配置跑出来的"；`config_hash` 就是为了让评测报告能自证配置。

3. **"日志用 structlog + contextvars 做 JSON 单行输出，trace_id 贯穿 8 个节点。"**
   —— 为什么：一次问答要定位"哪步慢、哪步空"，纯文本日志只能靠人眼拼接。被否决的方案是 `structlog.threadlocal` 与逐层传参：前者在线程池 `run_in_executor` 里会丢绑定（实测取到 `trace_id="-"`），后者要给每个函数签名加参数且漏传即断链。

4. **"我用确定性桩把 CI 与真实 API 解耦，CI 里真实调用数恒为 0。"**
   —— 为什么：LLM 输出不确定 + 单次 3–8s + 偶发 429，把真实 API 放进门禁会让门禁变成噪声；项目还有"尽量少用付费 API"的硬约束。被否决的方案是"CI 注入小额度真 Key"，理由是额度耗尽或网络抖动会造成与代码无关的红灯。桩的四剧本（正常／非法引用／应拒答／JSON 残缺）就是后续阶段的失败路径清单。

5. **"我在 Windows 上给 Milvus 做了双轨：容器栈起不来就自动降级到进程内 Milvus Lite。"**
   —— 为什么：本机 `com.docker.service` 常为 STOPPED，容器依赖会让"跑单测"变成"先开 Docker"。被否决的方案是"全改 faiss 手写索引"，理由是丢掉 Milvus 的标量过滤与分区能力；而 Lite 用同一套 `MilvusClient` API，切换只改一个 `MILVUS_URI` 变量——这才是双轨的价值。

### 10.2 风险与缓解

| # | 风险 | 触发信号 | 缓解措施 |
|---|---|---|---|
| R1 | `pip install -r requirements.txt` 在阿里云镜像上首次解析超时（镜像首页实测 13–20s，全量安装 1–3min） | 命令挂住超过 5min 无输出 | 设 `UV_HTTP_TIMEOUT=180`；失败重试一次（uv 缓存可复用）；仍失败切 `https://pypi.tuna.tsinghua.edu.cn/simple/`。**不要**改回 pypi.org（直连 000） |
| R2 | torch CUDA 版 wheel 2.67GB 下载中断 | `error: Failed to download` 或 hash mismatch | 该 wheel 直连 `download.pytorch.org` 实测 200 可下；中断就重跑（缓存已下分片）；实在不行先 `pip install -r requirements.txt --no-install-package torch` 跑通纯 CPU 路径，torch 单独补装 |
| R3 | Windows 无 milvus-lite 轮子，导致"降级路径"本身不可用 | `import milvus_lite` 失败 | 已锁 `milvus-lite>=3.1`（3.2.2 为 `py3-none-any`，本机实测建库/插入/检索全通）；CI 加一条 `uv run python -c "import milvus_lite"` 断言，防止依赖被"顺手降级"到 2.4.x |
| R4 | PS 5.1 编码/BOM 问题让脚本在队友机器上直接语法错 | 报"字符串缺少终止符" | 交付统一 UTF-8 with BOM；README 写明保存编码；两个脚本都不足 40 行，最坏情况可照文档复制命令手跑 |
| R5 | 配置模型与 S1–S6 文档字段漂移（S4 要 `judge`、S6 要 `cache`） | 后续阶段要往 `Settings` 加字段 | 加字段是**加法**不是改法：新增 Section 一律 `Field(default_factory=...)` 给默认值，旧 YAML 不写也能跑；`config_hash` 会变，评测报告靠 hash 区分，无需回填历史数据 |
