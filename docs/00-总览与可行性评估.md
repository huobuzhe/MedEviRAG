## 1. 结论摘要（先看这段）

**可行性判定：✅ 可以在本机完成，无需购买云资源，无不可绕过的技术阻塞。**

三条必须成立的前提，均已实测通过（见 §2）：
1. 有 ≥16GB 显存的消费级 GPU → 本地 bge-m3 + bge-reranker-v2-m3 可跑；
2. 有可用代理 + 国内 pip/模型镜像 → 依赖与权重可下载；
3. Docker Desktop 已安装但**守护进程默认不启动** → 需手动拉起，或走降级路径。

**原始设想的总体流程与框架方向正确，但有 7 处会被人问穿，必须在实施前修正：**

| # | 原始表述 | 问题 | 修正后（本项目采用） |
|---|---|---|---|
| 1 | 「按章节层级切分，避免固定长度切分把证据拦腰截断」 | 章节切分**不能**保证 chunk 不超长：指南的"推荐意见"节常只有 2 行，而"诊断标准"节可能 3000 字含表格。只说章节切分，实现时仍会被迫做二次定长切分，面试一问就露 | **父子双层（small-to-big）**：按章节树切出父节点（完整节），再在父节点内按语义边界切子块（200–400 token，表格/推荐意见整块不切），**子块建索引、父节点回填上下文**。切分层强制断言：每个 chunk 必须自带完整 `section_path`，且表格类 chunk 不得跨页合并 |
| 2 | 「向量 + BM25 + 元数据过滤的混合召回」 | 只说"混合"，没说**融合方式**与**为什么要融合**。且 Milvus 与 BM25 的部署形态有坑（Milvus Lite 对 BM25/sparse 的支持与本机降级路径冲突） | 明确为：**稠密向量检索（bge-m3）+ 稀疏检索（BM25）→ 单路各取 Top-K → RRF 融合 → 元数据硬过滤（发布年份/文种/文献类型/证据等级）**。融合用 RRF 而非加权和（两路分数量纲不可比），并保留加权和作为消融对照实验 |
| 3 | 「答案强制携带引用标记并回链原文」 | 只说了"强制"，没说**模型编造引用怎么办**。这是"可溯源"最容易崩的地方，面试必问 | 增加**引用后校验（citation grounding）**：生成后逐条校验每个 `[C1]` 是否命中召回集合、所支撑的句子是否被原文片段蕴含（NLI/LLM 校验二选一）；校验失败的句子降级为"证据不足"或整段拒答，**不允许未校验的引用直接返回** |
| 4 | 「置信度不足或证据等级不达标时按模板拒答」 | 「置信度」没有定义；证据等级字段在真实语料里**大量缺失**（很多指南不给 GRADE） | 置信度定义为**可计算的复合分**：最高重排分 + 引用覆盖率 + 证据等级加权 + 检索分差（top1 与 top5 的差距）。证据等级缺失时走 `unknown` 分支（不直接拒、也不直接放行，降级为"低置信"）；拒答规则全部是可枚举的**显式规则表**，每条规则有单元测试 |
| 5 | 「LLM-as-judge 三维自动打分」 | 用生成模型的同族模型自评有系统性偏好；只报分数不报**judge 与人评的一致性**，分数不可信 | 增加：rubric 拆到可判的原子项 + 温度 0 + 随机化候选顺序 + **人工标注 30 条做 judge 校准，报告一致率**；judge 模型与生成模型不同族 |
| 6 | 「【待填：评测集条数】」 | 条数决定结论强度。50 条以内的评测集，拒答准确率的 95% 置信区间宽到 ±14pp，写简历会被追问 | 定为目标 **160 条**：可答题 90（覆盖 12 个疾病主题）+ 应拒答题 50（越界/时效过期/个体化用药/证据不足四类）+ 多跳题 20。阶段 5 给出分层抽样与标注规范 |
| 7 | 技术栈同时写 Milvus + PostgreSQL/pgvector | **两套向量库重复**，面试官会问"为什么要两个向量库"，答不好就是堆技术栈 | **Milvus = 唯一向量库**；PostgreSQL 只承担**关系型职责**（文档元数据、章节树、评测集、审计日志、用户反馈），**不启用 pgvector**。简历改写为 "Milvus + PostgreSQL"，并备好"为什么不用 pgvector"的回答（见阶段文档 S6 与简历文档） |

> 另有 1 条被**否决**的加分项：「接入 MCP / Agent 工具调用」。否决理由：与"可溯源"主线无关，会稀释项目叙事，且在 96h 预算内不划算。若后续要加，放在 S6 之后的扩展清单里。

## 3. 可行性风险清单（按"会杀死项目"的程度排序）

| 级别 | 风险 | 触发条件 | 对策（已写入对应阶段验收） |
|---|---|---|---|
| 🔴 高 | 中文指南 PDF 解析质量差（双栏、扫描件、表格错位） | 一上手就批量跑 20 份 | S1 先做**单份 PDF 的解析质量评估**：抽 3 页人工对照，字符准确率 <95% 就换解析器（pymupdf → MinerU/unstructured → 人工剔除扫描件）。不达标不进下一步 |
| 🔴 高 | Docker 守护进程未启动导致 Milvus 连不上，全流程跑不动 | 每次开发都要手动开 Docker | S0 落地 `MILVUS_URI=./data/indexes/milvus_lite.db` 降级路径；**单元测试与评测必须能在无 Docker 下全绿**；集成测试标记 `@pytest.mark.docker` 单独跑 |
| 🟡 中 | 证据等级字段大面积缺失 | 语料里多数指南不给 GRADE | evidence extractor 输出 `unknown` 而非 `null` 静默；拒答规则表里有专门的 `unknown` 分支与对应测试用例；评测集里"证据不足型"题目专门覆盖它 |
| 🟡 中 | 端到端时延过高（本地 embed + rerank + API 生成叠加） | 每问 15s+ | 目标 P95 ≤ 6s；三段分别埋点（retrieval / rerank / generation），Redis 缓存 query embedding 与最终答案；rerank 候选数从 50 降到 20 |
| 🟡 中 | LLM API Key 缺失或额度耗尽 | 你没提供 Key | 生成层抽象为 `LLMClient` 接口，实现 OpenAI 兼容 / DashScope / 本地 vLLM 三个适配器；**评测与单测使用 `FakeLLM`（确定性桩）**，不依赖真实 API 也能验证管线 |
| 🟢 低 | 语料版权与合规 | 公开分发语料文件 | 语料只留在本地 `data/raw/`，`.gitignore` 排除；README 与 API 响应均带"仅供技术验证，不构成诊疗建议"声明 |
| 🟢 低 | 医疗结论被当真 | 对外演示 | 所有答案强制带免责声明字段；拒答模板含"请就医"引导 |

## 4. 系统总体架构

### 4.1 离线链路（离线索引 / Offline）

```
PDF/XML 原始语料
   │  ① 采集（fetcher，带 UA/限速/去重 hash）
   ▼
data/raw/*.pdf
   │  ② 解析（pymupdf/unstructured → 版面块：标题/正文/表格/图注 + 页码 + bbox）
   ▼
页级版面块
   │  ③ 章节树重建（sectionizer：靠字号/编号正则/目录页对齐，产出树 + section_path）
   ▼
章节树 JSON（父节点）
   │  ④ 语义切分（chunker：父节点内切子块，表格与推荐意见整块保留）
   ▼
chunks.jsonl（子块，含 parent_id / section_path / 页码 / token_len）
   │  ⑤ 元数据增强（metadata：doc_type/发布方/年份/证据等级/推荐强度）
   ▼
enriched chunks ──┬──► ⑥a 向量化（bge-m3，GPU 批处理）──► Milvus collection(dense)
                  └──► ⑥b BM25 倒排（bm25s/rank_bm25）  ──► BM25 索引文件
                                                                  │
                                              ⑦ PostgreSQL 写入：documents / sections / chunks / eval
```

### 4.2 在线链路（在线问答 / Online）

```
用户问题 (POST /v1/ask)
   │
   ▼
[LangGraph 状态图]  ┌───────────────────────────────────────────────────────┐
                    │ node1 route      : 意图归类（临床问答/越界/个体化用药）│
                    │ node2 rewrite    : 查询改写（术语扩展 + 同一问题多查询）│
                    │ node3 retrieve   : 稠密 Top50 ∥ BM25 Top50 → RRF 融合  │
                    │ node4 filter     : 元数据硬过滤（年份/文种/类型/等级） │
                    │ node5 rerank     : bge-reranker-v2-m3 交叉重排 → Top8  │
                    │ node6 generate   : 带编号上下文生成，强制 [C1]..[Cn]   │
                    │ node7 verify     : 引用落点校验 + 句级蕴含校验          │
                    │ node8 decide     : 置信度打分 → 应答 / 降级 / 拒答      │
                    └───────────────────────────────────────────────────────┘
   │
   ▼
响应 {answer, citations[{chunk_id, doc_title, section_path, page, quote, url}],
      status: answered|partial|refused, confidence, refusal_reason, disclaimer,
      trace:{各节点耗时}}
```

### 4.3 组件职责表

| 组件 | 职责 | 不负责 |
|---|---|---|
| `ingest/` | 采集、解析、章节树、切分、元数据、证据等级抽取 | 不碰向量与 LLM |
| `index/` | embedding、Milvus 读写、BM25 建/查、RRF 融合、过滤表达式 | 不做重排与生成 |
| `rag/` | LangGraph 编排、重排、生成 Prompt、引用校验、置信度与拒答 | 不直连存储原始 SQL |
| `serve/` | FastAPI 路由、Pydantic 契约、Redis 缓存、依赖注入、审计 | 不含业务规则 |
| `eval/` | 评测集构建、三个 judge、指标计算、报告生成、回归对比 | 不参与在线路径 |
| `common/` | 配置、日志（结构化 + trace_id）、类型、ID 生成、异常 | — |

**关键约束（贯穿所有阶段）：** `index/` 与 `rag/` **不得** import `serve/`；`eval/` 只能通过 `rag/` 的公开接口驱动评测，不得复制在线逻辑（否则评测与线上是两套行为，评测失去意义）。

## 6. 数据契约（全项目最重要的一张表）

### 6.1 Chunk Schema（`data/processed/chunks.jsonl`，一行一个 chunk）

```jsonc
{
  "chunk_id": "CN-HTN-2024#3.2.1#c02",     // doc_id#section_no#序号，全局唯一、可读、可回链
  "parent_id": "CN-HTN-2024#3.2.1",        // 父节点（small-to-big 回填用）
  "doc_id": "CN-HTN-2024",
  "doc_title": "中国高血压防治指南（2024年修订版）",
  "doc_type": "guideline",                 // guideline | consensus | paper | manual
  "publisher": "中国高血压联盟",             // 用于权威性加权
  "publish_year": 2024,                    // 用于时效过滤（>10 年降权/拒答）
  "lang": "zh",                            // zh | en
  "section_path": ["第3章 诊断与评估", "3.2 血压测量", "3.2.1 诊室血压"],
  "section_level": 3,
  "page_start": 27, "page_end": 27,
  "chunk_type": "recommendation",           // paragraph | recommendation | table | figure_caption | list
  "text": "推荐对诊室血压≥140/90 mmHg 者……（原文）",
  "context_header": "《中国高血压防治指南（2024年修订版）》 > 3.2.1 诊室血压",  // 拼进 embedding 与 prompt 的前缀
  "evidence_level": "A",                   // A|B|C|D|unknown（缺失写 unknown，不写 null）
  "rec_strength": "I",                     // I|IIa|IIb|III|unknown
  "grade_system": "指南自定",               // GRADE | 牛津 | 指南自定 | unknown
  "token_len": 312,
  "content_hash": "sha256:...",            // 去重与增量索引
  "locator": { "page": 27, "block_index": 4, "bbox": [72, 318, 523, 402] }  // 回链原文
}
```

**三条硬约束（S1 验收项）：**
- `chunk_type == "table"` 或 `"recommendation"` 时，**禁止跨节、禁止跨页合并**；超长则单独成块并在 `text` 内保留表头。
- 每个 chunk 的 `text` + `context_header` 必须能**独立读懂**（拿掉上下文后仍知"这是哪份指南的哪一节"）。
- `page_start == page_end` 且 `bbox` 非空 → API 才能做到"回链到页 + 高亮段落"。

### 6.2 PostgreSQL 表（S0 建表，S6 用起来）

## 7. 关键设计决策记录（ADR 摘要）

| ID | 决策 | 被否决的方案 | 理由（面试要能复述） |
|---|---|---|---|
| ADR-01 | **父章节 + 子块双层切分**（small-to-big） | 纯章节切分 / 纯固定 512 token 切分 | 纯章节切分粒度不均（一节可能 20 字也可能 3000 字），纯定长切分把剂量表与推荐意见拦腰截断。双层：**子块保证检索精度，父节点保证生成时的证据完整性** |
| ADR-02 | **稠密 + 稀疏双路召回，RRF 融合** | 纯向量；向量+BM25 加权和 | 医学查询里大量精确术语（"收缩压 140"、"eGFR<60"、药名剂量），向量对这类精确匹配天然弱，BM25 是补丁；两路分数量纲不可比，加权和要调权重且不稳定，**RRF 只看排名不看分数**，免调参且稳健 |
| ADR-03 | **元数据硬过滤放在融合之后、重排之前** | 过滤放在检索语句里（pre-filter） | pre-filter 在 Milvus 里会缩小候选池导致召回暴跌（尤其过滤条件选择性高时）。先宽召回再过滤，召回优先；代价是分两次检索，用 `filter_expr` 在 Milvus 侧做二次窄化 |
| ADR-04 | **引用必须后校验（grounding）** | 只靠 Prompt 要求模型"必须引用" | Prompt 只能提高概率，不能保证。模型会编 `[C9]` 或不引用。后校验是唯一的硬保证：**未通过校验的引用不返回给用户** |
| ADR-05 | **拒答是显式规则表 + 可计算置信度** | 让 LLM 自己判断"要不要拒答" | 医疗场景拒答必须可审计、可测试、可回归。交给模型 = 不可复现、无法写单测、无法解释误拒。规则表每条有名字、有阈值、有对应用例 |
| ADR-06 | **评测用确定性桩（FakeLLM）+ 真模型双轨** | 评测全依赖真实 API | CI 里跑真实 API 会因额度/网络随机失败，评测就没法当门禁。**单测与 CI 用 FakeLLM 验管线正确性，真模型只跑离线评测报告** |
| ADR-07 | **Milvus 唯一向量库，PG 只做关系型** | Milvus + pgvector 双写 | 双向量库=双份一致性负担、双份运维，且没有一条真实需求需要它。面试被问"为什么不用 pgvector"时答：**单机十万级 chunk 用 pgvector 完全够，选 Milvus 是为了练 HNSW/分区/标量混合过滤与分布式扩容路径，而不是因为 pgvector 不行**（诚实且显得懂取舍） |
| ADR-08 | **LangGraph 建图而非线性函数串联** | 一个 `answer(question)` 函数从头串到尾 | 需要**分支**（route 判定越界直接拒）、**可中断**（verify 失败回退到降级生成）、**每步可观测**（节点级耗时与状态）。线性函数做这些会变成 if-else 面条 |

## 13. 模型接入定案（实测于 m00077 之后，全项目唯一口径）

用户提供了三个 Key，我逐个实测。**以下为真实返回，各阶段文档不得另写别的路由。**

| 提供方 | Base URL | 实测结果 | 结论 |
|---|---|---|---|
| SiliconFlow | `https://api.siliconflow.cn/v1` | `GET /models` → **200**，98 个模型；`POST /chat/completions` model=`deepseek-ai/DeepSeek-V4.1-Flash` → **200** 且严格遵守"每断言后跟 [Cn]"并输出合法 JSON | ✅ **生成主用**，**必须直连**（走 Clash 代理 → 000） |
| DeepSeek 官方 | — | `401 {"code":30014,"message":"Token is invalid."}` | ❌ 提供的 Key 已被写在 URL 位置，无效，弃用 |
| 阿里百炼 DashScope | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `GET /models` → **200**，178 个模型；`POST /chat/completions` model=`qwen3.8-flash` → **200** 正常中文回答 | ✅ **judge 专用**，直连即可 |

**模型分工（一条不能改）：**

| 用途 | 模型 | 理由 |
|---|---|---|
| 生成 generator | SiliconFlow `deepseek-ai/DeepSeek-V4.1-Flash` | 实测能稳定产出带 `[Cn]` 的合法 JSON |
| 评测 judge | DashScope `qwen3.8-flash` | **必须与生成模型不同族**（ADR-05 的硬要求），DeepSeek 生成 / Qwen 判分正好互不偏袒 |
| 向量 embedding | 本地 `BAAI/bge-m3`（GPU） | 免费、可反复实验、不耗 API |
| 重排 reranker | 本地 `BAAI/bge-reranker-v2-m3`（GPU） | 同上；且 API 重排会把 P95 拖爆 |

> 备选（SiliconFlow 上也有，仅当本地 GPU 不可用时启用）：`BAAI/bge-m3`、`BAAI/bge-reranker-v2-m3`、`Qwen/Qwen3-Embedding-8B`、`Qwen/Qwen3-Reranker-8B`。

### 13.1 用户硬约束："用免费 API，尽量减少使用" → 三条工程纪律

1. **开发期与 CI 一律用 `FakeLLM`**（确定性桩）：任何单测、集成测试、CI 门禁**禁止**调真实 API。
2. **真实 API 只允许出现在两处**：① 阶段末跑一次离线评测报告；② judge 与人工标注的一致性校准。其余全部走桩或本地模型。
3. **token 预算护栏**：`configs/models.yaml` 增加
   ```yaml
   budget:
     max_total_tokens: 2000000      # 全项目预算上限
     per_run_warn: 200000           # 单次运行告警线
   ```
   LangGraph 每个节点累计 `usage.total_tokens`，超阈打 WARN 并落账；每份评测报告必须写"本次消耗 X tokens / Y 次调用"。

### 13.2 三个已实测的坑（S0 必须处理，否则后面每份文档都会踩）

1. **代理必须按 provider 分别配**：SiliconFlow `-x http://127.0.0.1:7890` → **HTTP 000**（代理反而阻断）；api.deepseek.com 官方域名则**必须**走代理。故 `configs/models.yaml` 要写成 `llm.proxy` 可按 provider 覆盖（siliconflow: null / deepseek-official: http://127.0.0.1:7890）。
2. **curl 发中文 JSON 不能写在 `-d '...'` 里**：Git Bash 下 UTF-8 会乱码（实测模型收到乱码后回了阿拉伯语）。正确做法是先写 body 到临时文件再 `--data-binary @file`；Python 侧用 `json.dumps(ensure_ascii=False).encode('utf-8')`。
3. **SiliconFlow 的模型名必须带厂商前缀**：是 `deepseek-ai/DeepSeek-V4.1-Flash`，不是 `DeepSeek-V4.1-Flash`；DashScope 侧则相反，是裸名 `qwen3.8-flash`。`qwen3.8-turbo` 不存在（404 model_not_found），别抄错。
