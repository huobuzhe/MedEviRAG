## 1. 阶段目标与边界

**S5 结束时「一定能做」的六件事：**

1. **一条命令出报告**：`uv run python -m medevirag.eval.runner --split dev` 产出 `data/reports/eval_<run_id>.json` 与 `data/reports/eval_<run_id>.md`；md 内含摘要卡、分维指标表、4 组消融表、失败案例 Top10 及归因。
2. **160 条评测集落地并冻结**：`data/eval/eval_set.jsonl` 共 160 条 = 可答 90 / 应拒 50 / 多跳 20，覆盖 12 个疾病主题（每主题 11–16 条）；`gold_chunk_ids` 经两人独立标注 + 分歧仲裁，逐对一致性 **Cohen's κ ≥ 0.70**；`data/eval/freeze.json` 记录 dev 128 / test 32 的 sha256 冻结戳，runner 每次启动强校验。
3. **三维 judge 可运行**：`judges.py` 逐题输出 `faithfulness / evidence_recall / refusal` 三个维度分，每维由 3–5 个原子 rubric 项加权（含 veto 项）；**温度 0、证据顺序按固定种子打乱、judge 模型 `qwen3.8-flash`（DashScope）与生成模型 `deepseek-ai/DeepSeek-V4.1-Flash`（SiliconFlow）**不同族****。
4. **judge 已校准**：`data/reports/judge_calibration.md` 存在，30 条人工标注，逐维报 judge 与人评的 Cohen's κ + 分歧案例三分类归因 + 一句「该维能否做门禁」的结论。
5. **回归门禁可用**：`uv run python -m medevirag.eval.regression --baseline <run_id> --current <run_id>` 输出逐题 delta 表（含「从对变错」清单，逐题带 `case_id` + 两版分维摘要 + 归因线索）；任一 00 §9 指标跌破阈值或单指标 delta 跌幅 > `hard_drop=0.05` 时**非零退出**。
6. **CI 双轨接线完成**：每个 PR 跑 FakeLLM 门禁（无网络、无 API Key、不下载权重、< 90s，含 golden metrics 断言与「故意注入回归必须被拦」的反向测试）；真模型评测走 nightly / 手动触发，报告作为 artifact 上传。

**S5 一定还不做的五件事：**

1. **不做 P95 压测与并发测试**：报告里 P95 只作为**观测列**记录，不设门禁（00 §9 的 ≤6s 属 S6 验收项）。
2. **不做评测看板 / 前端可视化**：只出 md + json，S6 前端不消费评测数据。
3. **不接入 RAGAS / TruLens / DeepEval 等第三方评测框架**：自研 judge 与指标，目的是让 rubric 与 S4 的 17 条拒答规则逐条对齐（理由见 §5.1、§5.3）。
4. **不做多轮对话评测与个性化评测**：全部单轮单问，跨轮指代消解不在本阶段。
5. **不重训/微调任何模型**，也不改 S2 的 `dense_topk=50`、`bm25_topk=50`、`rrf_k=60` 与 S3 的重排候选数；评测只消费已冻结产物，调参只能看 dev 子集。

### T1 · 类型契约、eval.yaml 与 token 预算护栏

### T2 · 分层抽样方案与配额矩阵

**要解决的问题**：160 条怎么分到 12 个主题、3 种题型、3 个难度档。**简单随机抽会在小主题上抽空**（骨质疏松相关 chunk 少），导致「覆盖 12 个疾病主题」没有证据。

### T3 · build_set.py 出题

**要解决的问题**：从数万个 chunk 里**可复现地**（同 seed 同结果）产出 160 条问句，并保证答案确实在那几个 gold chunk 里。

**关键实现思路**：三条渠道混合，避免全是 LLM 反向生成导致的「问句风格单一 + 把答案抄进问句」。

| 渠道 | 占比 | 做法 | 主要风险 |
|---|---|---|---|
| `chunk_reverse` | 40%（64 条） | 取单个 chunk 交生成模型：「只根据这段文本出 1 个临床医生会问的问题，不许拼接原文相邻两句」 | 问句把答案抄进去 → 需人工改写 + 泄漏检测 |
| `text_direct` | 40%（64 条） | 指南「推荐意见」与表格整块改写成问句，**该 chunk 直接作为唯一 gold，无需标注** | 偏容易，难度集中在 easy |
| `manual` | 20%（32 条） | 手工编写 + 人工指定 gold（含全部 20 条多跳与部分 stale / out_of_scope） | 慢，但这是唯一能造出真多跳题的渠道 |

**成本控制**：`chunk_reverse` 的 64 次生成调用是 S5 唯一的批量 API 消耗（约 64 × 700 tokens ≈ 45k）。做法是**先跑 FakeLLM 生成模板问句把流程与配额全部打通**，确认 160 条能落盘、配额断言通过、去重生效，**最后才**切真模型重跑一次出题，并把结果 commit 进 git（问句是静态资产，此后不再调用 API）。

```python
# src/medevirag/eval/build_set.py
import json, random, re
from pathlib import Path
from medevirag.common.types import EvalCase

SEED = 20240501

def load_pool(chunks_path: Path, keywords: dict[str, list[str]]) -> dict[str, list[dict]]:
    pool: dict[str, list[dict]] = {t: [] for t in keywords}
    with chunks_path.open(encoding="utf-8") as f:
        for line in f:
            c = json.loads(line)
            low = c["text"].lower()
            for topic, kws in keywords.items():
                if any(w.lower() in low for w in kws):
                    pool[topic].append(c)
    # 同主题内按权威性排序：guideline > consensus > paper > manual，同年份新者优先
    rank = {"guideline": 0, "consensus": 1, "paper": 2, "manual": 3}
    for t in pool:
        pool[t].sort(key=lambda c: (rank.get(c["doc_type"], 9), -(c.get("publish_year") or 0), c["chunk_id"]))
    return pool

def sample_one_topic(rng: random.Random, chunks: list[dict], n: int,
                     exclude: set[str]) -> list[dict]:
    """同主题内不重复取 n 个 chunk；优先 recommendation/table（最适合出题）。"""
    prefer = [c for c in chunks if c["chunk_type"] in ("recommendation", "table")
              and c["chunk_id"] not in exclude]
    rest = [c for c in chunks if c["chunk_id"] not in exclude]
    picked = rng.sample(prefer, min(n, len(prefer)))
    if len(picked) < n:
        taken = {c["chunk_id"] for c in picked}
        leftover = [c for c in rest if c["chunk_id"] not in taken]
        picked += rng.sample(leftover, min(n - len(picked), len(leftover)))
    return picked

def make_case_id(topic_code: str, case_type: str, idx: int) -> str:
    abbr = {"answerable": "A", "should_refuse": "R", "multi_hop": "M"}[case_type]
    return f"{topic_code}-{abbr}-{idx:03d}"

def jaccard(a: str, b: str) -> float:
    ta, tb = set(re.findall(r"\w+", a)), set(re.findall(r"\w+", b))
    return len(ta & tb) / max(1, len(ta | tb))

def dedup(cases: list[EvalCase], max_j: float = 0.85) -> list[EvalCase]:
    """问句去重：与已保留题目 Jaccard > 0.85 直接丢弃。"""
    kept: list[EvalCase] = []
    for c in cases:
        if all(jaccard(c.question, k.question) <= max_j for k in kept):
            kept.append(c)
    dropped = len(cases) - len(kept)
    if dropped:
        print(f"[dedup] dropped {dropped} near-duplicate questions")
    return kept

SECTION_NO_RE = re.compile(r"\d+\.\d+(?:\.\d+)?")

def assert_no_section_leak(cases: list[EvalCase]) -> None:
    """反向生成最常踩的坑：问句里抄了章节号，等于泄漏元数据。"""
    bad = [c.case_id for c in cases if SECTION_NO_RE.search(c.question)]
    if bad:
        raise SystemExit(f"SECTION_LEAK: {len(bad)} 条问句含章节编号，例如 {bad[:5]}")
```

**容易踩的坑**：
- 反向生成的问句会把 `section_path` 里的编号抄进去（「3.2.1 诊室血压中提到的……」），必须用正则扫（上面 `assert_no_section_leak`）。
- `rng.sample` 在 `len(population) < n` 时抛 `ValueError`：检查 3 已保证每主题 ≥ 30 chunk，但 `prefer` 子集可能不足，所以写了补偿分支。
- 用 ≠ 对象去重时依赖 `__hash__`，chunk 是 dict 不可哈希 → `exclude` 与 `taken` 一律按 `chunk_id` 字符串做集合，不要按对象。

### T4 · gold_chunk_ids 标注规范与 κ

**要解决的问题**：gold 标错，Recall@10 与 MRR 全部失真，且**无法事后发现**——这是评测里最贵的一种错。

**标注判据（三条全满足才标 gold）**：
1. **能独立回答问题**：拿掉上下文，只读该 chunk 的 `text + context_header` 就能回答该问句（正面或明确否定）。
2. **是原始出处**：优先指南正文/推荐意见/表格；二手综述段落只在无原始条款可标时才标。
3. **整块不切**：`chunk_type ∈ {table, recommendation}` 时整块算一个 gold，不允许只标表格里的一行。

**流程**：甲、乙两人各自独立标注（互不可见）→ 逐题算一致性 → 分歧逐条仲裁并写一句理由 → 仲裁结果作为最终 `gold_chunk_ids`。

**κ 的定义（集合标签怎么变成二分类）**：把每题候选池（检索 Top-10 + 人工补 5 = 15 个 chunk）展开成 15 个 `(case_id, chunk_id)` 判定对，每人给 0/1。160 × 15 = **2400 个判定对**，在这 2400 对上算标准 Cohen κ——分母大、估计稳定，二分类含义明确。`POOL_SIZE` 写成常量，报告里如实打印实际值。

**为什么池子还要人工补 5 个**：若池子只取检索 Top-10，「检索没召回但确实该算 gold」的 chunk 永远没机会被试出来，κ 会虚高、召回率会虚低。人工补的 5 个专抓这类漏网 gold，顺带量化 S2 的召回上限。

```python
# src/medevirag/eval/build_set.py（续）
from collections import Counter

POOL_SIZE = 15   # 每题候选池 = 检索 Top-10 + 人工补 5

def cohen_kappa(pairs: list[tuple[int, int]]) -> float:
    """pairs: [(label_a, label_b)] 均为 0/1。kappa = (po - pe) / (1 - pe)"""
    n = len(pairs)
    if n == 0:
        raise ValueError("no pairs")
    po = sum(1 for a, b in pairs if a == b) / n
    ca, cb = Counter(a for a, _ in pairs), Counter(b for _, b in pairs)
    pe = sum((ca.get(k, 0) / n) * (cb.get(k, 0) / n) for k in (0, 1))
    return 0.0 if pe == 1.0 else (po - pe) / (1.0 - pe)

def build_label_pairs(pool_map: dict[str, set[str]],
                      labels: dict[str, dict[str, set[str]]]) -> list[tuple[int, int]]:
    out: list[tuple[int, int]] = []
    for case_id, candidates in pool_map.items():
        a, b = labels["a"].get(case_id, set()), labels["b"].get(case_id, set())
        for cid in sorted(candidates):
            out.append((int(cid in a), int(cid in b)))
    return out

def arbitrate(case_id: str, a: set[str], b: set[str], arb: set[str], reason: str) -> set[str]:
    """arb 是仲裁人给的最终集合；必须断言它是 a|b 的子集，防止仲裁偷偷引入新 chunk。"""
    if not arb <= (a | b):
        raise SystemExit(f"{case_id}: 仲裁结果含未出现在两人标注里的 chunk，理由={reason}")
    return arb
```

**容易踩的坑**：`pairs` 全 0 或全 1 时 `pe == 1` 会除零；上面返回 0.0，并让报告单独显示 `po`（此时 κ 无解释力，如实写「该维两人几乎全标 0，κ 不具解释力」）。

### T5 · dev/test 80/20 划分与冻结

**要解决的问题**：00 §9 反作弊声明要求「任何调参只能看 dev，test 只在阶段末跑一次」。没有机器强制的约定等于没有约定。

**关键实现思路**：按 `case_type` **内部**做 80/20 分层切（90→72/18、50→40/10、20→16/4），保证 test 子集的题型分布与全集一致；冻结戳记录 `set_sha256` 与 `test_ids_hash`，runner 每次启动都校验。

```python
# src/medevirag/eval/build_set.py（续）
import hashlib
from dataclasses import replace
from datetime import datetime, timezone

def stratified_split(cases: list[EvalCase], seed: int = SEED) -> list[EvalCase]:
    rng = random.Random(seed)
    by_type: dict[str, list[EvalCase]] = {}
    for c in cases:
        by_type.setdefault(c.case_type, []).append(c)
    out: list[EvalCase] = []
    for ctype, group in by_type.items():
        group = sorted(group, key=lambda c: c.case_id)
        rng.shuffle(group)
        n_test = round(len(group) * 0.2)          # 90->18, 50->10, 20->4
        for i, c in enumerate(group):
            out.append(replace(c, split="test" if i < n_test else "dev"))
    return sorted(out, key=lambda c: c.case_id)

def _fingerprint(cases: list[EvalCase]) -> tuple[str, str]:
    """故意不含 question 文本：改错别字不应让全组历史报告作废（见下方坑）。"""
    ids = "\n".join(c.case_id for c in cases).encode()
    gold = json.dumps([sorted(c.gold_chunk_ids) for c in cases], ensure_ascii=False).encode()
    set_sha = hashlib.sha256(ids + b"\0" + gold).hexdigest()[:32]
    test_sha = hashlib.sha256(
        ",".join(c.case_id for c in cases if c.split == "test").encode()).hexdigest()[:32]
    return set_sha, test_sha

def freeze(cases: list[EvalCase], freeze_path: Path) -> dict:
    set_sha, test_sha = _fingerprint(cases)
    stamp = {
        "set_sha256": set_sha,
        "test_ids_hash": test_sha,
        "pool_size": POOL_SIZE,
        "n": {"dev": sum(c.split == "dev" for c in cases),
              "test": sum(c.split == "test" for c in cases)},
        "frozen_at": datetime.now(timezone.utc).isoformat(timespec="seconds"),
    }
    freeze_path.parent.mkdir(parents=True, exist_ok=True)
    freeze_path.write_text(json.dumps(stamp, ensure_ascii=False, indent=2), encoding="utf-8")
    return stamp

def verify_freeze(cases: list[EvalCase], freeze_path: Path, split: str) -> None:
    stamp = json.loads(freeze_path.read_text(encoding="utf-8"))
    set_sha, test_sha = _fingerprint(cases)
    if set_sha != stamp["set_sha256"]:
        raise SystemExit("FREEZE_MISMATCH: eval_set 被改动，需 git 恢复或显式 re-freeze 并说明原因")
    if split == "test" and test_sha != stamp["test_ids_hash"]:
        raise SystemExit("FREEZE_MISMATCH: test 子集成员被改动")
```

**容易踩的坑**：指纹故意**不含 question 文本**——否则改一个错别字就让全组历史报告不可比；代价是「改问句」不会被冻结拦下。所以报告必须同时打印 `set_sha256` 与 `git_sha`，靠 PR review 兜住；`--split test` 还要追加写 `data/eval/test_access_log.jsonl`（谁、何时、哪次 commit）。

### T6 · judges.py 三维 rubric

**要解决的问题**：把「忠实度 / 证据召回 / 合理拒答」变成可判的原子项，而不是一句「请给这段话打 1–5 分」。

**rubric 全文（`data/eval/rubric_v1.md`，代码里同步为常量）**：

| 维度 | 原子项 | 权重 | veto | 判据 |
|---|---|---|---|---|
| 忠实度 `faithfulness` | F1 | 3 | 否 | 答案中每条事实性断言都能在被引证据原文找到（允许同义改写，不允许新增数值） |
| | F2 | 3 | **是** | 答案里的数值、单位、阈值、年份与证据完全一致（证据「140/90 mmHg」不能写成「130/80」；「每日 1 次」不能写成「每日 2 次」） |
| | F3 | 2 | 否 | 无与证据矛盾的否定词/程度词（证据「可考虑」不能写成「推荐」；「不推荐」不能写成「慎用」） |
| | F4 | 2 | 否 | 无超出证据范围的外推（不得补充指南未提及的检查、药物、随访间隔） |
| | F5 | 1 | 否 | 每个 `[Cn]` 的位置与其支撑句语义对应（不是整段只挂一个引用） |
| 证据召回 `evidence_recall` | E1 | 3 | 否 | 至少 1 个 gold chunk 出现在本次生成所用上下文中 |
| | E2 | 3 | 否 | gold 中的关键数值/结论出现在上下文里（gold 命中但关键行被截断 → 失败） |
| | E3 | 2 | 否 | 无 gold 证据被元数据过滤误杀（落在召回集合却被 filter 阶段剔除 → 失败） |
| 合理拒答 `refusal` | R1 | 4 | **是** | `status` 与 `must_refuse` 匹配（应拒必拒、可答不该拒）；`partial` 计为 answered 但单列统计 |
| | R2 | 2 | 否 | 拒答时 `refusal_reason` 与 `gold_refuse_kind` 一致 |
| | R3 | 2 | 否 | 拒答文案含三要素：为什么拒 + 建议怎么做 + 就医/指引 |
| | R4 | 2 | 否 | 可答题的答案里不出现「我无法回答/资料不足」这类弃权话术 |

`veto=True` 的项失败则该维直接 **0 分**（不是扣分）：F2 失败意味着剂量或阈值写错，任何加权平均都会掩盖这条最危险的错误；R1 同理——应拒却答了，是医疗场景最严重的失败形态。

**打分示例（真实落的判定）**
题 `HTN-A-014`：「老年高血压患者的降压目标值是多少？」gold = `CN-HTN-2024#3.4.2#c01`
答案：「老年高血压患者血压目标为 **<150/90 mmHg**，若能耐受可降至 <140/90 mmHg [C1]。」
judge 输出：
```json
{"items":[{"item_id":"F1","ok":true,"why":"两句均由 C1 原文可找到"},
          {"item_id":"F2","ok":true,"why":"150/90、140/90 与原文一致"},
          {"item_id":"F3","ok":true,"why":"无程度词偏移"},
          {"item_id":"F4","ok":true,"why":"无额外检查或药物"},
          {"item_id":"F5","ok":true,"why":"C1 挂在结论句尾"}],
 "reason":"全项通过"}
```
→ `score = (3+3+2+2+1)/(3+3+2+2+1) = 1.0`，`passed = True`。
反例：答案写成「目标 <140/90 mmHg」→ F2 失败（证据主结论是 150/90，140/90 只是「能耐受」的次级目标，作为主结论即错）→ veto → `score = 0.0`。

```python
# src/medevirag/eval/judges.py
import json, random
from dataclasses import dataclass
from medevirag.common.types import EvalCase, JudgeScore

@dataclass(frozen=True, slots=True)
class RubricItem:
    item_id: str
    dim: str
    weight: int
    veto: bool
    ask: str

RUBRIC_V1: tuple[RubricItem, ...] = (
    RubricItem("F1", "faithfulness", 3, False, "答案中每条事实性断言都能在被引证据原文中找到"),
    RubricItem("F2", "faithfulness", 3, True,  "答案里的数值/单位/阈值/年份与证据完全一致"),
    RubricItem("F3", "faithfulness", 2, False, "无与证据矛盾的否定词或程度词"),
    RubricItem("F4", "faithfulness", 2, False, "无超出证据范围的外推"),
    RubricItem("F5", "faithfulness", 1, False, "每个 [Cn] 的位置与其支撑句语义对应"),
    RubricItem("E1", "evidence_recall", 3, False, "至少 1 个 gold chunk 出现在本次生成所用上下文中"),
    RubricItem("E2", "evidence_recall", 3, False, "gold 中的关键数值/结论出现在上下文里"),
    RubricItem("E3", "evidence_recall", 2, False, "无 gold 证据被元数据过滤误杀"),
    RubricItem("R1", "refusal", 4, True,  "status 与 must_refuse 匹配"),
    RubricItem("R2", "refusal", 2, False, "拒答 reason 与 gold_refuse_kind 一致"),
    RubricItem("R3", "refusal", 2, False, "拒答文案含为什么拒+建议+就医指引"),
    RubricItem("R4", "refusal", 2, False, "可答题答案不含弃权话术"),
)

JUDGE_SYSTEM = (
    "你是严格的医学证据审核员。只依据给定的【证据原文】判断，不得使用你自己的医学知识。"
    "对每个 rubric 项必须给出 ok(bool) 与 why(不超过 30 字)。只输出 JSON，不要任何解释性前后缀。"
)

def shuffle_evidence(evidence: list[dict], seed: int) -> list[dict]:
    """位置偏差对策：按固定种子打乱证据顺序，judge 永远看不到原始排名。"""
    idx = list(range(len(evidence)))
    random.Random(seed).shuffle(idx)
    return [evidence[i] for i in idx]

def build_prompt(case: EvalCase, answer: str, evidence: list[dict], dim: str,
                 seed: int, status: str, citation_map: dict[str, str]) -> list[dict]:
    items = [it for it in RUBRIC_V1 if it.dim == dim]
    ev = shuffle_evidence(evidence, seed)
    ev_text = "\n\n".join(
        f"[证据{i+1}] chunk_id={e['chunk_id']} 来源={e['doc_title']} > {' / '.join(e['section_path'])}\n{e['text']}"
        for i, e in enumerate(ev))
    cmap = "\n".join(f"{k} -> {v}" for k, v in citation_map.items())
    user = (
        f"【问题】{case.question}\n"
        f"【系统答案】{answer}\n"
        f"【系统给出的拒答状态】{status}\n"
        f"【答案里的引用标记与 chunk_id 对应关系】\n{cmap}\n"
        f"【证据原文（顺序已打乱，编号与答案里的 [Cn] 无关）】\n{ev_text}\n\n"
        "【本维度要判的项】\n"
        + "\n".join(f"- {it.item_id}（权重{it.weight}{'，一票否决' if it.veto else ''}）：{it.ask}" for it in items)
        + "\n\n【输出 JSON】{\"items\": [{\"item_id\": \"<上列 id>\", \"ok\": true, \"why\": \"<=30字\"}]}"
    )
    return [{"role": "system", "content": JUDGE_SYSTEM}, {"role": "user", "content": user}]

def aggregate(dim: str, atomic: dict[str, bool]) -> tuple[float, bool]:
    items = [it for it in RUBRIC_V1 if it.dim == dim]
    if any(it.veto and not atomic.get(it.item_id, False) for it in items):
        return 0.0, False
    num = sum(it.weight for it in items if atomic.get(it.item_id, False))
    den = sum(it.weight for it in items)
    score = num / den
    return score, score >= 0.80

def judge_dim(case: EvalCase, answer: str, evidence: list[dict], dim: str, llm, cfg,
              status: str, citation_map: dict[str, str]) -> JudgeScore:
    want = {it.item_id for it in RUBRIC_V1 if it.dim == dim}
    atomic: dict[str, bool] = {}
    for attempt in range(cfg.judge.max_retry + 1):
        raw = llm.chat(build_prompt(case, answer, evidence, dim,
                                    cfg.judge.evidence_order_seed, status, citation_map),
                       temperature=0.0, max_tokens=cfg.judge.max_tokens)
        try:
            obj = json.loads(raw[raw.index("{"): raw.rindex("}") + 1])
            atomic = {i["item_id"]: bool(i["ok"]) for i in obj["items"]}
            if set(atomic) != want:
                raise ValueError(f"rubric 项不匹配 want={sorted(want)} got={sorted(atomic)}")
            break
        except (ValueError, KeyError) as e:
            if attempt == cfg.judge.max_retry:
                return JudgeScore(case.case_id, dim, 0.0, False, {}, cfg.judge.model,
                                  case.rubric_version, error=f"judge_parse_failed: {e}")
    score, passed = aggregate(dim, atomic)
    return JudgeScore(case.case_id, dim, score, passed, atomic, cfg.judge.model, case.rubric_version)

def assert_cross_family(gen_model: str, judge_model: str) -> None:
    """自我偏好对策：生成族与判分族不得相同（00 §1 第 5 条）。"""
    fam = {"deepseek": "deepseek", "qwen": "qwen", "gpt": "openai", "claude": "anthropic"}
    if fam.get(gen_model.split("-")[0]) == fam.get(judge_model.split("-")[0]):
        raise SystemExit(
            f"CROSS_FAMILY_VIOLATION: gen={gen_model} judge={judge_model} 同族，judge 分不可信")
```

**容易踩的坑**：
- 证据顺序打乱后，答案里的 `[C1]` 与 prompt 里的「证据1」**不再对应**。prompt 必须显式声明这一点，并额外给出 `citation_map`（`C1 -> chunk_id`），否则 F5 会被系统性误判。
- judge 输出常带 JSON 围栏或前置寒暄，用 `raw.index("{")` 到 `rindex("}")` 截取比正则稳。
- 温度 0 不等于完全确定：模型版本更新、`max_tokens` 截断都会变。所以 `judge_error_rate ≤ 0.05` 是必备闸门，报告必须记 `judge_model + rubric_version`。
- judge 每次都要判三维 = 每题 3 次调用。160 条 × 3 次 = **480 次 judge 调用**，单次约 1.5k prompt tokens → 约 72 万 tokens。这是 S5 最大的 API 开销，因此：**先拿 20 条小样本跑通**，确认 rubric 无歧义、JSON 100% 可解析，再全量跑；跑 dev 用的 128 条（384 次）而不是全量 160 条。

### T7 · judge 校准（30 条人工标注）

**要解决的问题**：「未校准的自动打分只是另一个模型的意见」（00 §10 S5 行原话）。要能回答「这个 0.83 的忠实度凭什么信」。

**30 条分层抽**：15 可答 / 12 应拒 / 3 多跳。应拒给到 12 条是因为 R1 是 veto 项，判错的代价最高。

**人工标注口径**：人评者只回答**维度级「通过/不通过」**（阈值 0.80），不看 judge 的原子项拆解，避免被 judge 的推理带偏。人评者 = 主标 + 复核人；**若确实找不到第二位标注者，改用「主标 + 间隔 ≥ 3 天盲复评」，并在报告里如实写明这是单标注者 + 延迟重评，κ 的解释力弱于双人独立标注**——不许含糊。

```python
# src/medevirag/eval/metrics.py（校准部分，与 T8 同文件）
from collections import Counter

def cohen_kappa_binary(a: list[int], b: list[int]) -> dict:
    assert len(a) == len(b) and a, "两边标注数必须相等且非空"
    n = len(a)
    po = sum(1 for x, y in zip(a, b) if x == y) / n
    ca, cb = Counter(a), Counter(b)
    pe = sum((ca.get(k, 0) / n) * (cb.get(k, 0) / n) for k in (0, 1))
    kappa = 0.0 if pe == 1.0 else (po - pe) / (1 - pe)
    return {"n": n, "po": round(po, 4), "pe": round(pe, 4), "kappa": round(kappa, 4)}

KAPPA_BANDS = ((0.20, "轻微 slight"), (0.40, "尚可 fair"), (0.60, "中等 moderate"),
               (0.80, "强 substantial"), (1.01, "几乎完全一致 almost perfect"))

def band(kappa: float) -> str:
    for th, name in KAPPA_BANDS:
        if kappa < th:
            return name
    return "几乎完全一致 almost perfect"
```

**分歧案例三类归因（报告逐条列，每条 1 行）**：
1. **阈值歧义**：同一句「部分支撑」（证据说「可考虑」，答案说「推荐」）人判过、judge 判不过 → 对策：把 F3 判据改成可枚举措辞表（可考虑≠推荐，不推荐≠慎用）。
2. **上下文缺失**：judge 只看本次 Top-8，人评时凭常识补了 → 对策：E 维只用「本次上下文」，人评也只看上下文（口径统一到弱的一方）。
3. **话术口径**：`partial` 算不算拒答 → 对策：定死 `partial` 计入 `answered`，报告单列 `partial_rate`。

**落盘**：`data/reports/judge_calibration.md` 必须含抽样清单、逐维 κ 表（`n / po / pe / kappa / band`）、分歧条目明细、**结论段**（例：「忠实度 κ=0.71 可用于门禁；拒答 κ=0.52 仅作参考，门禁以 S4 规则表的确定性判定为准」）。

### T8 · metrics.py：00 §9 全部指标

**要解决的问题**：指标实现最容易被「看起来对」骗过去（分母错、topk 切片错、nDCG 的 IDCG 用错序）。每条都要有单测。

```python
# src/medevirag/eval/metrics.py
import math, random
from statistics import mean
from typing import Sequence

def recall_at_k(gold: Sequence[str], retrieved: Sequence[str], k: int = 10) -> float:
    """主口径：gold 集合在 Top-K 里的覆盖率（比 hit@k 更严，见 §5.2）。"""
    if not gold:
        raise ValueError("gold_chunk_ids 为空：每条题必须至少 1 个 gold")
    return len(set(gold) & set(retrieved[:k])) / len(set(gold))

def hit_at_k(gold: Sequence[str], retrieved: Sequence[str], k: int = 10) -> float:
    return 1.0 if set(gold) & set(retrieved[:k]) else 0.0

def mrr(gold: Sequence[str], retrieved: Sequence[str]) -> float:
    g = set(gold)
    for i, cid in enumerate(retrieved, start=1):
        if cid in g:
            return 1.0 / i
    return 0.0

def ndcg_at_k(graded: dict[str, int], retrieved: Sequence[str], k: int = 10) -> float:
    """graded: chunk_id -> rel(2/1/0)。2=gold，1=同父节点兄弟块，0=其他。"""
    dcg = sum((2 ** graded.get(c, 0) - 1) / math.log2(i + 2) for i, c in enumerate(retrieved[:k]))
    ideal = sorted(graded.values(), reverse=True)[:k]
    idcg = sum((2 ** r - 1) / math.log2(i + 2) for i, r in enumerate(ideal))
    return dcg / idcg if idcg > 0 else 0.0

def citation_landing_rate(dangling: int, total: int) -> float:
    if total == 0:
        raise ValueError("答案里没有引用：落点正确率无定义，应记 status=fail 而不是 0")
    return (total - dangling) / total

def sentence_support_rate(sentences: Sequence[dict]) -> float:
    """只统计含引用的句子；一条引用都没有时抛错，由 runner 记 fail。"""
    cited = [s for s in sentences if s["cited_chunk_ids"]]
    if not cited:
        raise ValueError("无含引用的句子")
    return sum(1 for s in cited if s["landing_ok"] and s["entailed"]) / len(cited)

def refusal_recall(rows: Sequence[dict]) -> float:
    den = sum(1 for r in rows if r["must_refuse"])
    if den == 0:
        raise ValueError("没有应拒答题，拒答召回无定义")
    return sum(1 for r in rows if r["must_refuse"] and r["status"] == "refused") / den

def over_refusal_rate(rows: Sequence[dict]) -> float:
    den = sum(1 for r in rows if not r["must_refuse"])
    if den == 0:
        raise ValueError("没有可答题，过度拒答率无定义")
    return sum(1 for r in rows if not r["must_refuse"] and r["status"] == "refused") / den

def refusal_reason_accuracy(rows: Sequence[dict]) -> float:
    refused = [r for r in rows if r["status"] == "refused"]
    if not refused:
        raise ValueError("没有拒答样本")
    return sum(1 for r in refused if r["refusal_reason"] == r["gold_refuse_kind"]) / len(refused)

def bootstrap_ci(flags: Sequence[bool], n_boot: int = 2000, alpha: float = 0.05,
                 seed: int = 7) -> tuple[float, float]:
    rng, n = random.Random(seed), len(flags)
    if n == 0:
        return (float("nan"), float("nan"))
    means = sorted(sum(flags[rng.randrange(n)] for _ in range(n)) / n for _ in range(n_boot))
    return means[int(alpha / 2 * n_boot)], means[int((1 - alpha / 2) * n_boot) - 1]

def expected_calibration_error(confs: Sequence[float], corrects: Sequence[bool],
                               n_bins: int = 10) -> float:
    """S4 遗留的正式标定报告在此出：ECE = Σ (n_b/N)·|acc_b − conf_b|"""
    bins: list[list[tuple[float, bool]]] = [[] for _ in range(n_bins)]
    for c, ok in zip(confs, corrects):
        bins[min(int(c * n_bins), n_bins - 1)].append((c, ok))
    total = len(confs)
    return sum(len(b) / total * abs(sum(ok for _, ok in b) / len(b) - sum(c for c, _ in b) / len(b))
               for b in bins if b)

def mean_or_none(xs: Sequence[float]) -> float | None:
    """空分母返回 None（渲染成 n/a），绝不填 0——0 会被读成「表现极差」。"""
    return mean(xs) if xs else None
```

**一次算完的入口**（run 结果 → 指标 dict，即 `eval_runs.metrics jsonb` 的内容）：

```python
# src/medevirag/eval/metrics.py（续）
HIGHER_IS_BETTER = {
    "recall_at_10": True, "mrr": True, "ndcg_at_10": True, "citation_landing_rate": True,
    "sentence_support_rate": True, "faithfulness": True, "refusal_recall": True,
    "refusal_reason_accuracy": True,
    "over_refusal_rate": False,        # 上限型：越低越好
    "judge_error_rate": False,
}

def compute_all(rows: list[dict], cfg) -> dict:
    """rows 每题一条：case_id/case_type/must_refuse/gold_chunk_ids/retrieved/graded/
       status/refusal_reason/gold_refuse_kind/confidence/correct/
       dangling_citation_count/total_citation_count/sentences/judge/judge_error/metric_flags"""
    ok_rows = [r for r in rows if not r["judge_error"]]
    m: dict = {"n": len(ok_rows), "n_total": len(rows),
               "judge_error_rate": round(1 - len(ok_rows) / len(rows), 4)}
    m["recall_at_10"] = mean_or_none([recall_at_k(r["gold_chunk_ids"], r["retrieved"], 10) for r in ok_rows])
    m["hit_at_10"] = mean_or_none([hit_at_k(r["gold_chunk_ids"], r["retrieved"], 10) for r in ok_rows])
    m["mrr"] = mean_or_none([mrr(r["gold_chunk_ids"], r["retrieved"]) for r in ok_rows])
    m["ndcg_at_10"] = mean_or_none([ndcg_at_k(r["graded"], r["retrieved"], 10) for r in ok_rows])
    m["faithfulness"] = mean_or_none(
        [r["judge"]["faithfulness"] for r in ok_rows if "faithfulness" in r["judge"]])
    m["evidence_recall"] = mean_or_none(
        [r["judge"]["evidence_recall"] for r in ok_rows if "evidence_recall" in r["judge"]])
    m["citation_landing_rate"] = mean_or_none(
        [citation_landing_rate(r["dangling_citation_count"], r["total_citation_count"])
         for r in ok_rows if r["total_citation_count"] > 0])
    m["sentence_support_rate"] = mean_or_none(
        [sentence_support_rate(r["sentences"]) for r in ok_rows
         if any(s["cited_chunk_ids"] for s in r["sentences"])])
    m["refusal_recall"] = refusal_recall(ok_rows)
    m["over_refusal_rate"] = over_refusal_rate(ok_rows)
    m["refusal_reason_accuracy"] = refusal_reason_accuracy(ok_rows)
    m["ece"] = expected_calibration_error([r["confidence"] for r in ok_rows],
                                          [r["correct"] for r in ok_rows])
    m["partial_rate"] = mean_or_none([1.0 if r["status"] == "partial" else 0.0 for r in ok_rows])
    for key, higher in HIGHER_IS_BETTER.items():
        if key not in m or m[key] is None:
            continue
        lo, hi = bootstrap_ci([r["metric_flags"][key] for r in ok_rows])
        m[f"{key}_ci95"] = [round(lo, 3), round(hi, 3)]
        th = getattr(cfg.eval.thresholds, key, None)
        m[f"{key}_pass"] = None if th is None else (m[key] >= th if higher else m[key] <= th)
    return m
```

**容易踩的坑**：`mean([])` 会抛 `StatisticsError`。所有空分母一律返回 `None` 并在报告显示 `n/a`，**绝不填 0**。`total_citation_count == 0` 的题不进落点率分母，但在失败案例里单列（「一条引用都没有」本身就是缺陷）。

### T9 · runner.py 与 report.py

**要解决的问题**：一条命令跑完「读集 → 逐题调管线 → 调 judge → 算指标 → 出 md/json」，且 `run_id` 可追溯；报告要能在一个屏幕内看出「这次比上次差在哪」。

**关键实现思路**：runner **只经 `rag/` 公开接口**（`build_graph() / invoke()`）驱动，不复制节点逻辑（00 §4.3）；所有耗时/token 在节点侧累加，runner 只汇总。

```python
from medevirag.eval.report import render_markdown, render_ablation

def config_hash(cfg_paths: list[Path], prompt_dir: Path) -> str:
    """配置 + prompt 模板一起进 hash：改 prompt 必须改变 run_id，否则 delta 表会把两次不同实验对齐。"""
    h = hashlib.sha256()
    for f in sorted(cfg_paths) + sorted(prompt_dir.glob("*.j2")):
        h.update(f.name.encode())
        h.update(f.read_bytes())
    return h.hexdigest()[:12]

def git_sha() -> str:
    return subprocess.check_output(["git", "rev-parse", "--short=7", "HEAD"], text=True).strip()

def make_run_id(sha: str, chash: str, split: str) -> str:
    ts = datetime.now(timezone.utc).strftime("%Y%m%dT%H%M")
    return f"{ts}_{sha}_{chash}_{split}"

def run_one(case, graph, judge_llm, cfg) -> dict:
    t0 = time.perf_counter()
    resp = graph.invoke({"question": case.question})   # 只走 S3 公开入口
    latency_ms = (time.perf_counter() - t0) * 1000
    row = {
        "case_id": case.case_id, "case_type": case.case_type,
        "must_refuse": case.must_refuse, "gold_chunk_ids": list(case.gold_chunk_ids),
        "gold_refuse_kind": case.refuse_kind,
        "retrieved": resp["retrieved_chunk_ids"],
        "graded": resp.get("graded_relevance", {c: 2 for c in case.gold_chunk_ids}),
        "status": resp["status"], "refusal_reason": resp.get("refusal_reason"),
        "confidence": float(resp.get("confidence", 0.0)),
        "dangling_citation_count": resp["citation_report"].dangling,
        "total_citation_count": resp["citation_report"].total,
        "sentences": resp["citation_report"].sentences,
        "latency_ms": latency_ms, "judge": {}, "judge_error": False,
    }
    assert_cross_family(cfg.eval.generator.model, cfg.eval.judge.model)
    for dim in ("faithfulness", "evidence_recall", "refusal"):
        js = judge_dim(case, resp["answer"], resp["context_chunks"], dim, judge_llm,
                       cfg, resp["status"], resp["citation_map"])
        if js.error:
            row["judge_error"] = True
            row["judge_error_msg"] = js.error
        else:
            row["judge"][dim] = js.score
    row["correct"] = bool(row["judge"].get("faithfulness", 0) >= 0.8
                          and row["judge"].get("refusal", 1) >= 0.8)
    row["metric_flags"] = {
        "recall_at_10": bool(set(case.gold_chunk_ids) & set(resp["retrieved_chunk_ids"][:10])),
        "mrr": M.mrr(case.gold_chunk_ids, resp["retrieved_chunk_ids"]) > 0,
        "ndcg_at_10": M.ndcg_at_k(row["graded"], resp["retrieved_chunk_ids"], 10) >= 0.7,
        "faithfulness": row["judge"].get("faithfulness", 0.0) >= 0.8,
        "refusal_recall": (resp["status"] == "refused") if case.must_refuse else True,
    }
    return row

def main(split: str = "dev", allow_test: bool = False, limit: int | None = None) -> dict:
    cfg = load_cfg("configs/eval.yaml", "configs/models.yaml")
    cases = load_cases(cfg.eval.set_path)
    verify_freeze(cases, cfg.eval.freeze_path, split)          # 冻结强校验，先于任何调用
    if split == "test" and not allow_test:
        raise SystemExit("test 子集被冻结：必须显式 --allow-test，且会在 test_access_log 落账")
    subset = [c for c in cases if c.split == split]
    if limit:
        subset = subset[:limit]                                 # 小样本冒烟，20 条起步
    graph, judge_llm = build_graph(cfg), build_judge_llm(cfg)
    sha, chash = git_sha(), config_hash([Path("configs/eval.yaml"), Path("configs/models.yaml")],
                                        Path("rag/prompts"))
    run_id = make_run_id(sha, chash, split)
    rows = [run_one(c, graph, judge_llm, cfg) for c in subset]
    m = M.compute_all(rows, cfg)
    m.update({"run_id": run_id, "git_sha": sha, "config_hash": chash, "split": split,
              "seed": cfg.eval.sample_seed,
              "frozen_set_sha256": json.loads(Path(cfg.eval.freeze_path).read_text())["set_sha256"],
              "usage": graph.usage_summary()})                  # tokens_used / api_calls
    out_dir = Path(cfg.eval.reports_dir); out_dir.mkdir(parents=True, exist_ok=True)
    (out_dir / f"eval_{run_id}.json").write_text(
        json.dumps({"metrics": m, "cases": rows}, ensure_ascii=False, indent=2), encoding="utf-8")
    (out_dir / f"eval_{run_id}.md").write_text(
        render_markdown(m, rows, render_ablation(cfg)), encoding="utf-8")
    print(f"[eval] {run_id} faithfulness={m['faithfulness']} recall@10={m['recall_at_10']}")
    return m
```

**消融表怎么来**：用 `configs/eval.yaml` 的 `ablation:` 段驱动 4 组重跑，每组只改一个开关：①`retrieval.fusion=rrf` vs `weighted_sum`；②`rerank.enabled=false`；③`filter.enabled=false`（验证 ADR-03「硬过滤在融合后重排前」的价值）；④`refusal.rules=off`（关 S4 规则表）。**消融只在 dev 子集上跑，且默认不进 CI**（4 组 × 128 条 = 512 次管线调用，太贵），只在阶段末报告里手动跑一次。

**容易踩的坑**：
- `run_id` 必须含 `config_hash`。否则「改了 prompt 但忘了改版本号」时，两次 run 的 delta 会被当同配置比较，结论全错。
- `config_hash` 要把 `rag/prompts/*.j2` 一起算进去；只 hash yaml 是 S5 最容易漏的一处。
- `limit` 参数只为冒烟（先 20 条），**不许**用它出正式报告——报告摘要卡必须打 `n` 实际条数，避免「用 20 条冒充 128 条」。

### T10 · regression.py 回归门禁

**要解决的问题**：「这次改动让哪些题从对变错」——只说「忠实度掉了 0.03」没法定位。

**关键实现思路**：双 run 逐题 join，输出三张表（变差 / 变好 / 持平但接近阈值），并**在任一门禁触发时以退出码 2 结束**，供 CI 直接判定。

```python
# src/medevirag/eval/regression.py
import json, sys
from pathlib import Path

GATED = ("recall_at_10", "mrr", "ndcg_at_10", "citation_landing_rate",
         "sentence_support_rate", "faithfulness", "refusal_recall",
         "over_refusal_rate", "refusal_reason_accuracy")

def load_run(path: Path) -> dict:
    d = json.loads(path.read_text(encoding="utf-8"))
    d["by_case"] = {c["case_id"]: c for c in d["cases"]}
    return d

def compare(base: dict, cur: dict, cfg) -> tuple[list[dict], list[str]]:
    problems: list[str] = []
    if base["metrics"]["frozen_set_sha256"] != cur["metrics"]["frozen_set_sha256"]:
        problems.append("FREEZE_MISMATCH: 两次 run 用的评测集指纹不同，不可比较")
    # 1) 绝对阈值门禁
    for key in GATED:
        v, th = cur["metrics"].get(key), getattr(cfg.eval.thresholds, key)
        higher = key != "over_refusal_rate"
        if v is None:
            continue
        if (higher and v < th) or (not higher and v > th):
            problems.append(f"THRESHOLD_FAIL {key}={v} 目标{'≥' if higher else '≤'}{th}")
    # 2) 相对跌幅门禁
    delta = []
    for key in GATED:
        b, c = base["metrics"].get(key), cur["metrics"].get(key)
        if b is None or c is None:
            continue
        d = round(c - b, 4)
        better = (d >= 0) if key != "over_refusal_rate" else (d <= 0)
        if not better and abs(d) > cfg.eval.regression.hard_drop:
            problems.append(f"HARD_DROP {key}: {b} -> {c} (Δ={d})")
        delta.append({"metric": key, "base": b, "cur": c, "delta": d,
                      "status": "worse" if not better else "ok"})
    # 3) 逐题 diff：只挑从对变错 / 从错变对的
    diff = []
    for cid in sorted(set(base["by_case"]) & set(cur["by_case"])):
        b, c = base["by_case"][cid], cur["by_case"][cid]
        bc, cc = b["correct"], c["correct"]
        if bc == cc:
            continue
        diff.append({
            "case_id": cid, "direction": "regressed" if bc else "fixed",
            "base": {k: b["judge"].get(k) for k in ("faithfulness", "evidence_recall", "refusal")},
            "cur":  {k: c["judge"].get(k) for k in ("faithfulness", "evidence_recall", "refusal")},
            "base_status": b["status"], "cur_status": c["status"],
            "base_refusal_reason": b.get("refusal_reason"),
            "cur_refusal_reason": c.get("refusal_reason"),
            "hint": attribute(cid, b, c),          # 归因线索，见下
        })
    return diff, problems

def attribute(cid: str, b: dict, c: dict) -> str:
    """三分类归因：检索 / 生成 / 判定。用可观测差异定，不猜。"""
    if b["retrieved"][:10] != c["retrieved"][:10]:
        return "retrieval: Top-10 顺序或成员变了"
    if (b["total_citation_count"] - b["dangling_citation_count"]) != \
       (c["total_citation_count"] - c["dangling_citation_count"]):
        return "generation: 引用落点数变了"
    if b["status"] != c["status"]:
        return f"refusal: {b['status']} -> {c['status']}"
    return "judge: 检索与生成产物一致，差异来自判分（先查 rubric/模型版本）"

def main(base_id: str, cur_id: str) -> int:
    cfg = load_cfg("configs/eval.yaml", "configs/models.yaml")
    base = load_run(Path(cfg.eval.reports_dir) / f"eval_{base_id}.json")
    cur = load_run(Path(cfg.eval.reports_dir) / f"eval_{cur_id}.json")
    diff, problems = compare(base, cur, cfg)
    md = render_delta_md(base_id, cur_id, diff, problems)
    out = Path(cfg.eval.reports_dir) / f"delta_{base_id}_vs_{cur_id}.md"
    out.write_text(md, encoding="utf-8")
    for p_ in problems:
        print("[GATE]", p_, file=sys.stderr)
    print(f"[delta] {len(diff)} 题方向变化，报告 {out}")
    return 2 if problems else 0
```

**阈值怎么定（回答「回归门禁怎么设阈值」）**：
1. **绝对底线**用 00 §9 的九个数字，直接抄，不改。
2. **相对跌幅**分两档：`max_drop=0.02` 是噪声带（dev 128 条、单指标二项分布的标准误约 `sqrt(0.85×0.15/128)≈0.032`，0.02 略小于 1 个标准误 → 不报警是对的）；`hard_drop=0.05` 超过约 1.5 个标准误 → 必须人工看。**没有分档，门禁要么天天红（0.005 就报）要么永远绿（只在 0.2 才报），两种都等于没有门禁。**
3. **口径绑定**：`hard_drop` 只能配 128 条 dev 用；若有人偷偷用 20 条小样本跑对比，标准误升到 0.08，门禁必然误报 → 所以 `compare()` 要断言两次 run 的 `n` 相同，不同则直接拒绝比较。

**容易踩的坑**：`main` **不要**用 `sys.exit(2)` 之外的方式表达失败；GitHub Actions 只看退出码，`print("[FAIL]")` 不会被拦。

### T11 · CI 接线（ADR-06 双轨）

**要解决的问题**：把评测放进 CI，但**不能**让「API 额度耗尽 / 网络抖动」变成 PR 的红灯。这就是 ADR-06 的存在理由。

**为什么这样分（ADR-06 原文逻辑）**：
- 若 PR 门禁依赖真实 API：①硅基流动有 QPS/额度限制，多人同时 PR 会 429；②PR 来自 fork 时拿不到 secret，门禁直接不可用；③模型厂商偶发 5xx，工程师会习惯性点「重跑」，门禁失去权威；④每次 PR 花几万 token，成本不可控（用户明确要求「尽量少用 API」）。
- 所以 PR 只验证**管线正确性**：给定同一份 FakeLLM 确定性输出，指标必须等于 golden 值。这能抓住「分母写错、topk 切片错、nDCG 的 IDCG 用错序、门禁方向判反」这四类真 bug——它们与模型质量无关，却占回归的绝大多数。
- 模型质量回归只能靠真模型：放 nightly / 手动触发。它慢（20–40 分钟）、花钱、依赖网络，但它回答的是「换模型/改 prompt 究竟有没有变好」，这件事一晚上一次足够。

## 5. 知识点讲解

### 5.1 为什么 RAG 评测必须拆「检索」与「生成」两段

**是什么**：端到端只看「答案好不好」是一个复合指标；拆开看，一个 RAG 系统的失败可归为三类：检索没召回（retrieval miss）、召回了但没用上或用错（generation error）、用对了但被判错（judge error）。

**为什么需要**：`检索 Recall@10 = 0.62` 与 `生成忠实度 = 0.95` 放在一起，端到端正确率仍只有 0.6 左右——此时优化 prompt 是白费力气，天花板由检索决定。不拆段就没有优先级。

**在本项目怎么用**：`metrics.py` 的输出天然分三组（检索组 / 生成组 / 拒答组），报告的分维表按组排；失败案例的 `attribute()` 四分类（retrieval / generation / refusal / judge）就是这件事的落地。判据：若 `recall_at_10 = 0.88` 而 `faithfulness = 0.71`，说明天花板够但生成在丢信息，优先改 S3 的上下文组织；反之若 `recall_at_10 = 0.66 < 0.85`，改 prompt 一律无效。

**常见误解**：「端到端正确率能替代分维指标」。不能——端到端正确率的分母混合三种失败，任一改善都会被另两个稀释，128 条样本上根本看不出来（1 条题 = 0.78 个百分点）。

### 5.2 Recall@K 与 hit@K 差在哪，为什么要报 Recall

**公式**：Recall@K = |gold ∩ top-K| / |gold|；hit@K = 1 当且仅当 gold ∩ top-K 非空。

**为什么需要**：多跳题有 2–3 个 gold。`hit@10` 只要命中最容易的那个就记 1.0，会系统性高估。本项目的 20 条多跳题若各含 2 个 gold，`hit@10 = 1.0` 时 `recall@10` 可能只有 0.5——后者才反映「证据是否齐全」。

**在本项目怎么用**：主口径用 `recall_at_10`（00 §9 目标 0.85），`hit@10` 只作诊断列。两者差距 > 0.10 时说明多 gold 题普遍只命中 1 个，去看 E1/E2 两项 judge 分。

**常见误解**：「Recall 高就代表检索好」。Recall 是**集合**覆盖，不含排序信息；全部 gold 都排在第 10 位时 Recall=1.0 但 MRR≈0.1。所以 00 §9 同时要求 MRR ≥ 0.62 与 nDCG@10 ≥ 0.70。

### 5.3 LLM-as-judge 的三种已知偏差与对策

**位置偏差（position bias）**：judge 倾向认可靠前的内容。同一对候选对调顺序，LLM 判定翻转率经验值可达 **10%–25%**。
→ 对策：`shuffle_evidence()` 用固定种子 `evidence_order_seed=7` 打乱证据顺序，并在 prompt 里显式写「编号与答案里的 [Cn] 无关」，另给 `citation_map` 兜住 F5。

**长度偏差（verbosity bias）**：越长越像「详细」，judge 给高分，即使内容更差。
→ 对策：rubric **原子化**，12 个原子项没有一项是「是否详细」；F4 直接惩罚「超出证据范围的外推」，越啰嗦越容易踩 F4。报告同时打印平均答案长度，若某次改动让长度涨 40% 而忠实度也涨，先怀疑这种偏差。

**自我偏好（self-preference）**：judge 对同族模型输出打分偏高（同一 tokenizer 与训练分布重叠）。本项目的硬约束：**生成 `deepseek-ai/DeepSeek-V4.1-Flash`（SiliconFlow），判分 `qwen3.8-flash`（DashScope）**，由 `assert_cross_family()` 在每次 run 前断言，同族直接 `SystemExit`。

**第四条易被忽略的偏差——采样**：判分必须 `temperature=0.0`，否则同一输入两次判定不同，κ 无从谈起。注意温度 0 **不等于**完全可复现（厂商侧批处理、模型版本更新都会变），所以要有 `judge_error_rate ≤ 0.05` 与 `judge_model + rubric_version` 落盘。

**常见误解**：「多加几个 rubric 项就更准」。项越多否决链越长，judge 一致性往往下降；12 项（5+3+4）是本项目可维护的上限。

### 5.4 Cohen's κ：为什么不能只报「一致率」

**公式**：κ = (p_o − p_e) / (1 − p_e)，其中 p_e = Σ_c P(a=c)·P(b=c)。

**为什么需要**：本项目 gold 标注里「不标」占绝大多数（15 个候选通常只有 1–2 个 gold，阴性率约 87%）。两人**都全标 0** 也能拿到 p_o = 0.87 的「一致率」——看起来漂亮，实际毫无信息量。κ 把「靠猜也能达到的一致」扣掉：p_e = 0.87 时 p_o = 0.87 对应 κ = 0。

**判读表（Landis & Koch，§4 T7 的 `KAPPA_BANDS` 就是这套）**：<0.20 轻微 / 0.20–0.40 尚可 / 0.40–0.60 中等 / 0.60–0.80 强 / 0.80–1.00 几乎完全一致。本项目的线：gold 标注 κ ≥ 0.70（0.60 起可接受，低于 0.60 必须重标）；judge 校准 κ ≥ 0.60 才允许该维进 CI 门禁。

**数字示例（本项目 2400 个判定对的典型形态）**：两人各标 200 个正例、重叠 170 个，则 p_o = (170 + 2060)/2400 = 0.929；p_e = (200/2400)² + (2200/2400)² = 0.0069 + 0.8403 = 0.847；κ = (0.929 − 0.847)/(1 − 0.847) = **0.54** → 「中等」，该改标注判据，而不是宣称「92.9% 一致」。

**常见误解**：「κ 高就代表标得对」。κ 只说明两人**互相一致**；两人一起系统性标错（比如都把二手综述当原始出处）时 κ 照样很高。所以还要仲裁 + 抽 10 条回查原文。

### 5.5 为什么评测集必须冻结（80/20 划分 + 指纹）

**是什么**：`freeze.json` 记录 `set_sha256 / test_ids_hash / n{dev,test} / frozen_at`；runner 每次启动先 `verify_freeze()`。

**为什么需要**：不冻结会出现三种作弊，且都是**无意识**的：①看到某题答错就去改那题的 `gold_chunk_ids`（把标准往模型输出靠）；②反复在 test 上调 prompt，等价于把 test 变成 dev；③悄悄删掉 3 道难题凑指标。这三种在 128 条样本上足以让忠实度虚高 0.05–0.08。

**在本项目怎么用**：80/20 按 `case_type` 内部切（90→72/18、50→40/10、20→16/4）；`--split test` 必须配 `--allow-test` 并写 `test_access_log.jsonl`；指纹故意不含 `question` 文本（改错别字不作废历史报告），因此报告必须同时打印 `git_sha + set_sha256` 让 PR review 兜住。

**常见误解**：「冻结就是不能再改」。冻结拦的是**悄悄改**：要改就走 re-freeze 并在报告里写明原因 + 版本号加一，历史报告保留但不可比。医学指南会更新（`publish_year` 变化），重标是正常的工程动作。

### 5.6 回归门禁的阈值怎么定（噪声带 vs 硬跌）

**为什么需要**：指标均值在 128 条样本上是随机变量。以二值 flag 计，标准误 SE = sqrt(p(1−p)/n) = sqrt(0.85×0.15/128) ≈ **0.032**。也就是说两次 run 之间 0.03 的差异完全可能是噪声。

**在本项目怎么用**：`max_drop=0.02`（小于 1 个 SE，不报警）、`hard_drop=0.05`（约 1.5 个 SE，必须人工介入或回滚）。同时用 bootstrap（`n_boot=2000`、`seed=7`）给每个指标报 95% CI；**两次 run 的 CI 大幅重叠时不许宣布「变好了」**。绝对底线仍用 00 §9 的九个数字，不动。

**一个容易漏的约束**：`hard_drop` 只对 128 条有效。用 20 条冒烟时 SE ≈ 0.080，5 个百分点完全在噪声内 → `compare()` 必须断言两次 run 的 `n` 相同，不同直接拒绝比较。

**常见误解**：「阈值越严越好」。`max_drop=0.005` 会让 nightly 天天红，团队两周后习惯性忽略；`max_drop=0.2` 等于没有门禁。分档 + 双向（绝对底线 + 相对跌幅）才可维持。

### 5.7 token 预算与评测成本的可计算性

**数字**：dev 128 条 × 3 维 judge = **384 次 judge 调用**；单次 prompt ≈ 1.5k tokens（8 条证据 + rubric），completion ≈ 150 tokens → 约 **63 万 tokens**。加上生成侧 128 × 约 1.8k = 23 万，单次真模型 dev 评测 ≈ **86 万 tokens**。

**为什么需要**：用户明确要求「尽量少用 API」。不把成本算清楚，评测会变成「不敢跑」的摆设。

**在本项目怎么用**：`configs/models.yaml` 的 `budget: {max_total_tokens: 2000000, per_run_warn: 200000, enforce: warn}`；LangGraph 每节点累加 `usage`，`graph.usage_summary()` 进报告摘要卡（「384 次调用 / 71.2 万 tokens」）。三档策略：开发用 FakeLLM（0 tokens）→ 冒烟 `--limit 20`（约 11 万）→ 正式 dev 评测一次（约 86 万）→ test 阶段末一次（约 22 万）。

**常见误解**：「judge 比生成便宜可以随便跑」。judge 调用次数是生成侧的 3 倍且 prompt 更长，实际是**成本大头**（约 73%）。

### 6.4 反作弊自查（与 00 §9 声明逐条对齐）

1. 摘要卡必须同时打印 `frozen_set_sha256`、`git_sha`、`config_hash`、抽样种子与 n——缺任一项视为报告无效。
2. 调参只看 dev（128 条）；test（32 条）只在阶段末跑一次，`test_access_log.jsonl` 每行都有时间戳与 commit。
3. 任何「提升」都必须附 bootstrap 95% CI；两次 run 的 CI 大幅重叠时**不许**写提升。
4. `--limit` 只用于冒烟：摘要卡上的 n 必须等于实际跑的数量，不许用 20 条的结果冒充 128 条。
5. 报告必须打印 token 消耗与调用次数（用户要求「尽量少用 API」，成本必须可见）。

## 7. 常见问题与排查

### Q1 · 报错关键字：`SSLError: HTTPSConnectionPool(host='api.siliconflow.cn' ...)` / `HTTP 000` / 请求 30s 无响应

**原因**：SiliconFlow 与 DashScope **必须直连**，被 Clash 的 HTTP 代理劫持后表现为 000 或超时。而这台机器上 `api.deepseek.com` 官方域名反过来**必须**走代理，两者结论相反，很容易一把 `HTTP_PROXY` 全局设上去就全挂。
**解法**：按 provider 分别配代理，别用全局环境变量。

```yaml
# configs/models.yaml
llm:
  generator:
    provider: siliconflow
    base_url: https://api.siliconflow.cn/v1
    model: deepseek-ai/DeepSeek-V4.1-Flash
    proxy: null                      # 直连，绝对不能走代理
    temperature: 0.0
  judge:
    provider: dashscope
    base_url: https://dashscope.aliyuncs.com/compatible-mode/v1
    model: qwen3.8-flash
    proxy: null                      # 直连
    temperature: 0.0
  # 仅本地对照用，正式评测不使用
  deprecated_reference:
    provider: deepseek-official
    base_url: https://api.deepseek.com/v1
    proxy: http://127.0.0.1:7890     # 官方域名必须走代理
```

排查三连：`curl --noproxy '*' -s -o NUL -w "%{http_code}" https://api.siliconflow.cn/v1/models -H "Authorization: Bearer $KEY"`（PowerShell 用 `curl.exe`，不能用别名）；拿到 200 再跑评测。

### Q2 · 报错关键字：`{"code":30014,"message":"Token is invalid."}` / 401

**原因**：DeepSeek 官方那个 Key 实测无效（用户填的是 URL 不是 Key），401 就是这么来的。注意这跟「网络不通」是两回事——401 说明**链路通了但凭证错**。
**解法**：不要拿 DeepSeek 官方 Key 做评测，生成侧用 SiliconFlow 的 `deepseek-ai/DeepSeek-V4.1-Flash`（同族模型，仍是 DeepSeek 家族但走 SiliconFlow 网关）。键名统一 `SILICONFLOW_API_KEY` / `DASHSCOPE_API_KEY`，写进 `.env`（已 gitignore），CI 用 GitHub Secrets。

### Q3 · 报错关键字：`curl` 返回一串阿拉伯语/乱码，或 `{"error":{"message":"Invalid request"}}` 而 body 看起来正常

**原因**：Windows + Git Bash 下把中文 JSON 直接写在 `-d '...'` 里，命令行编码与 UTF-8 不一致，服务端收到的是坏字节。
**解法**：body 写临时文件再 `--data-binary @file`：

```bash
cat > /tmp/judge_probe.json <<'JSON'
{"model":"qwen3.8-flash","temperature":0,
 "messages":[{"role":"user","content":"请只回复：中文编码正常"}]}
JSON
curl --noproxy '*' -s https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions \
  -H "Authorization: Bearer $DASHSCOPE_API_KEY" \
  -H "Content-Type: application/json" \
  --data-binary @/tmp/judge_probe.json
```

PowerShell 5.1 版本：`Invoke-RestMethod -Uri ... -Body ([System.Text.Encoding]::UTF8.GetBytes($json)) -ContentType 'application/json'`，注意 5.1 的 `curl` 是 `Invoke-WebRequest` 别名，要网关类调用必须写 `curl.exe`。

### Q4 · 报错关键字：`AttributeError: 'str' object has no attribute 'get'` 或 `judge 解析失败率 0.31`

**原因**：judge 返回的不是纯 JSON（被 markdown 围栏包住、带中文前言、或截断）。qwen3.8-flash 在 `temperature=0` 下偶尔仍会输出 ```json` 围栏。
**解法**：`parse_judge_json()` 做三级兜底（去围栏 → 取第一个 `{` 到最后一个 `}` → 正则抽单项分）；仍失败则记 `judge_error`，不把失败当 0 分（当 0 分会系统性低估）。报告里 `judge_error_rate > 0.05` 时本次 run 作废重跑，而不是改阈值糊过去。

### Q5 · 报错关键字：`FrozenSetMismatch: eval_set fingerprint changed`

**原因**：改了 `data/eval/eval_set.jsonl` 但没重新冻结，或改的是 `question` 文本导致指纹变化。
**解法**：先看 diff 是「修错别字」还是「改 gold」——
- 修错别字：允许，重跑 `build_set freeze --reason "typo"` 并升 `set_version`（历史报告保留、标注不可比）。
- 改 gold / 换题：属于作弊面，必须写进 PR 描述并重跑 κ。
紧急调试可 `--allow-freeze-mismatch`（仅本地，CI 里禁止）。

### Q6 · 报错关键字：`ConnectionError: HTTPSConnectionPool(host='www.modelscope.cn' ...)` 第一次跑 eval 卡在模型加载

**原因**：评测第一次运行要加载 bge-m3 / bge-reranker-v2-m3，`models/` 下没有权重时会去下载；pypi 与 HF 直连都不通，hf-mirror.com 只有根域名能通、文件路径连续两次 25s 超时 HTTP 000（挂代理也是 000），所以必须走 ModelScope。
**解法**：

```bash
uv pip install modelscope
uv run modelscope download --model BAAI/bge-m3 --local_dir models/bge-m3
uv run modelscope download --model BAAI/bge-reranker-v2-m3 --local_dir models/bge-reranker-v2-m3
```

然后 `configs/models.yaml` 里把路径写死成绝对/相对本地目录，`local_files_only: true`，评测过程零下载。CI 用 FakeEmbedding（`MEDEVIRAG_EMBEDDING=fake-hash`）根本不碰权重。

### Q7 · 报错关键字：`RuntimeError: Docker daemon not running` / `MilvusException: failed to connect`

**原因**：Docker Desktop 装了但 `com.docker.service` 是 STOPPED，评测脚本如果硬编码 `localhost:19530` 就起不来。
**解法**：评测路径必须走 Milvus Lite 降级：`MILVUS_URI=./data/indexes/milvus_lite.db`。判定口径：`os.getenv("MILVUS_URI", "").endswith(".db")` → Lite 模式。CI 里显式设这个变量，保证无 Docker 也全绿。注意 Lite 单进程独占，同一时刻只能一个评测进程打开，跑并行会报锁错误。

### Q8 · 报错关键字：`kappa = 0.41 (< 0.70)`，但两人「看起来标得一样」

**原因**：κ 惩罚的是「阴性共识」带来的虚高。2400 个判定对里阴性占 87%，p_o 高而 p_e 也高，κ 就被压下来。真正常见的根因有两类：①判据没写清「二手引用算不算 gold」；②两人对 `chunk_type=table` 的处理不同。
**解法**：不要放宽阈值，回去统一判据（§4 T4 三条判据逐条对齐），只重标分歧的 200–300 个判定对，再重算。低于 0.60 必须整批重标。

### Q9 · 症状：CI 的 `eval-fake` job 通过但耗时 6 分钟、偶发失败

**原因**：fake 模式仍走了真实 embedding（下载模型）或 `bootstrap_ci(n_boot=2000)` 在 160 条 × 9 指标上串行跑。前者是网络依赖，后者是纯 CPU 浪费。
**解法**：①断言环境变量 `MEDEVIRAG_EMBEDDING=fake-hash` 与 `NO_NETWORK=1`；②`n_boot` 在 CI 里降到 200（`configs/eval.yaml` 的 `bootstrap.n_boot_ci: 200`），本地报告才用 2000；③用 `pytest -n auto`（需要 pytest-xdist，已装）把 3 个测试文件拆开跑。目标 < 90s。

### Q10 · 症状：`pytest tests/eval` 本地全绿，GitHub Actions 上红

**原因**：三种典型差异——①本地 `data/eval/eval_set.jsonl` 是 dev 分支的临时版本；②`models.yaml` 的 `proxy: null` 在 CI 里被缓存的全量配置覆盖；③路径分隔符 `/` 与 `\`。前两者靠「CI 里禁读 `.env`、配置从 `configs/` 唯一来源加载」解决；路径统一用 `pathlib.Path` 拼接，不手写字符串。

## 8. 面试可讲点

**1. 我把评测拆成「检索 / 生成 / 拒答」三组指标，而不是只报一个端到端准确率。**
为什么这么做：第一版只有端到端正确率 0.61，改了一周 prompt 没动 —— 拆开才发现 `Recall@10 = 0.66 < 0.85` 是天花板，改 prompt 等于在漏水的桶上贴胶带。被否决的方案：只报 EM/F1，问题是一个数字无法定位失败层，也解释不了「为什么加 rerank 没用」。

**2. judge 用 Qwen、生成用 DeepSeek，硬性禁止同族。**
为什么：LLM 有自我偏好（self-preference），同族打分系统性偏高，会让忠实度虚高 3–8 个点。我在 `assert_cross_family()` 里把它做成启动断言，配错直接 `SystemExit`，而不是靠 code review 记得。被否决的方案：用同一个 DeepSeek 既生成又判分——省一个 Key，但整个忠实度指标就失去意义。

**3. 报 Cohen's κ 而不是「一致率 92.9%」。**
为什么：2400 个判定对里 87% 是阴性，两人都标 0 就有 92.9% 的一致率，信息量为零；κ 扣掉阴性共识后是 0.54，直接暴露「二手引用算不算 gold」的判据不一致。被否决的方案：报原始一致率 —— 漂亮但没有约束力，标注质量无法追责。

**4. 评测集 dev/test 80/20 切分后冻结指纹，test 只在阶段末跑一次。**
为什么：不冻结就会有三种无意识作弊（改 gold 迎合模型、反复在 test 上调 prompt、删难题凑分），在 128 条样本上足以让忠实度虚高 0.05–0.08。冻结的实现是 `set_sha256 + test_ids_hash + test_access_log.jsonl` 三件套。被否决的方案：靠流程纪律「大家别动测试集」——没有技术约束的纪律在赶工时一定破。

**5. 回归门禁用「绝对底线 + 相对跌幅」双轨，阈值来自噪声带计算而不是拍脑袋。**
为什么：128 条样本上二值指标的 SE = sqrt(0.85×0.15/128) ≈ 0.032，所以 `max_drop=0.02`（< 1 SE 不报警）与 `hard_drop=0.05`（≈1.5 SE 必须介入）是有依据的；同时 `compare()` 断言两次 run 的 n 相同，20 条冒烟不能跟 128 条基线比。被否决的方案：拍 `max_drop=0.05` —— 在 20 条冒烟上 SE 是 0.08，5 个点根本是噪声。

**6. CI 用 FakeLLM 跑门禁、真模型评测手动触发（ADR-06）。**
为什么：真模型依赖 API Key、额度与网络，一旦抖动机器就红，团队会开始忽略红灯；FakeLLM 确定性桩可以断言「管线正确性」（字段是否齐、引用是否可解析、拒答分支是否走到），这些才是 PR 该拦的。被否决的方案：每次 PR 都跑真模型评测 —— 慢、贵、且随机红。
