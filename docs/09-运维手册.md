# 运维手册（S6 T9）

> 适用环境：F:\MedEviRAG，Windows 11，GPU RTX 4060 Ti。
> 无 Docker 时的手工路径是本机主路径；Docker 路径为部署机交付。

## 1. 启动 / 停止

### 1.1 无 Docker 手工启动（本机主路径）

```powershell
Set-Location F:\MedEviRAG
$env:PYTHONPATH = "src"
$env:MEDEVIRAG_DEVICE = "cpu"          # 服务器有 GPU 时改为 cuda
$env:TRANSFORMERS_CACHE = "data/.hf_cache"
.\.venv\Scripts\python.exe -X utf8 -m uvicorn medevirag.serve.app:app --host 0.0.0.0 --port 8000 --workers 1
```

就绪检查：`curl.exe -s http://127.0.0.1:8000/readyz`——本机无 PG/Redis 时 `postgres` 与 `redis` 两项 `ok=false` 属**预期降级**（审计走 `data/logs/qa_log.jsonl`、缓存走进程内），`models` 与 `milvus` 必须 `ok=true`。

### 1.2 Docker 全栈（部署机）

```powershell
Copy-Item .env.example .env   # 填入两个 API Key
docker compose -f docker/docker-compose.yml --env-file .env up -d
docker compose -f docker/docker-compose.yml ps   # 6 服务全 healthy
```

停止：`docker compose -f docker/docker-compose.yml down`（保留数据）；`down -v` 连数据卷一起清（会删 Milvus 索引，慎用）。

## 2. 查日志

| 内容 | 位置 |
|---|---|
| API 运行日志 | uvicorn 控制台（JSON 结构化） |
| 审计日志（无 PG） | `data/logs/qa_log.jsonl`（每问一行，含 trace_id 与四段耗时） |
| 反馈（无 PG） | `data/logs/feedback.jsonl` |
| 按 trace_id 检索 | `Select-String "trace_id" data/logs/qa_log.jsonl` |

## 3. 压测

```powershell
$env:PYTHONPATH = "src"; .\.venv\Scripts\python.exe -X utf8 scripts/loadtest.py --concurrency 20 --repeat 3
```

P95 ≤ 6000ms 达标；`partial_rate > 0.30` 判为"靠降级达标"需复测。

## 4. 四类故障处置

| 症状 | 判定 | 处置 |
|---|---|---|
| `docker compose up` 报 `Cannot connect to the Docker daemon` | Docker Desktop 未启动 | 启动 Docker Desktop；或走 §1.1 手工路径（无需 Docker） |
| `[Errno 10048] bind on 8000` | 端口占用 | `netstat -ano | findstr :8000` 找 PID 后 `taskkill /PID <pid> /F`；或换 `--port 8001` |
| `/readyz` 503 且 `failed==["models"]` | 预热失败 | 看响应体 `detail` 与 uvicorn 日志 `warmup failed`；常见为 chunk 索引未建（先跑 `index` 子命令） |
| 前端 `blocked by CORS policy` | 5173 直连 8000 未带 CORS | `configs/app.yaml` 的 `serve.cors_origins` 已含 5173；或开发期直接用 `npm run dev`（vite proxy 转发，天然同源） |

## 5. 前端

```powershell
Set-Location web; npm install; npm run dev   # http://127.0.0.1:5173
```
